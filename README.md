## GPS 안내·경로 재생 — 기술 시연 버전

길 찾기 결과에서 **GPS 안내 시작** 또는 **경로 GPS 재생**을 선택할 수 있습니다. 선분 기준 진행·다음 구간·잔여 거리·위치 품질·지속 이탈을 표시하고, 일시정지·재개·종료와 휴식·도착 확인을 제공합니다. 재생은 실제 위치가 아닌 모의 위치입니다. 먼저 PC에서 재생으로 확인하세요.

현재 GPS는 현장 통행이 검증되지 않은 기술 시연이며, 위험 대안은 일반 GPS 시작을 제한합니다. 재탐색은 원래 이동 조건을 유지하는 수동 ‘현재 위치에서 다시 찾기’로 제공하고 자동 실행은 실기기 검사 전 보류합니다. 기존 기본 GPS 핀·최근접 노드 진행 추정은 새 안내 세션으로 교체했습니다.

[내비게이션 구현 현황·실제 화면·휴대폰 HTTPS 준비](donghaeng-nav/docs/navigation-implementation.md). Android·iPhone 실기기와 현장 검사는 사용자 요청에 따라 나중에 진행합니다. 기존 남쪽/3km 경로와 미검증 출입구가 해결된 것으로 간주하지 마세요.

## 모바일 이용 — 2026-11-01 갱신

화면 너비 700px 이하에서는 지도와 접이식 하단 패널을 사용하는 모바일 화면이 열립니다. 목적지·상태 문장 입력 → 경로 비교 → 이동 순서로 전환하며, 하단의 길 찾기·저장·제보 탭으로 이동합니다. 패널 제목을 누르면 접거나 펼칠 수 있고 손잡이를 위로 밀면 확장됩니다. 시설 버튼을 열면 패널이 접혀 지도 공간을 확보합니다. 출발지의 ‘변경’에서 GPS 또는 지도 핀을 선택할 수 있습니다.

손잡이·제목을 잡고 위아래로 끌면 패널이 손가락을 실시간으로 따라오며, 놓으면 위치·속도에 따라 접힘·중간·펼침 높이에 부드럽게 안착합니다. 본문 맨 위의 빈 곳이나 일반 텍스트에서도 아래로 끌어 패널을 내릴 수 있습니다. 본문을 이미 스크롤한 상태에서는 내용 스크롤이 유지됩니다. 입력칸·버튼은 원래 조작을 유지하며, 시스템의 모션 줄이기 설정도 반영합니다.

키보드 입력 중에는 패널을 넓히고, 상태 문장은 기존처럼 길 찾기 한 번으로 해석합니다. 결과의 ‘상태 해석·경로 근거 보기’에서 상세 자료와 제한 사항을 확인하세요. 이동 순서는 수동 구간 확인이며 자동 회전 안내가 아닙니다. 비교 시연과 이용 안내는 상단 `⋯` 메뉴에 있습니다. PC에서는 기존 두 열 화면과 발표 모드를 이용합니다.

[모바일 구현·검증 기록과 실제 화면](donghaeng-nav/docs/mobile-ux-implementation.md). 온라인 타일·AI는 아래 로컬 서버 실행 방법을 따르며, 파일 단독 실행은 내장 지도·기기 내 해석을 사용합니다.

작성 기준: 2026-10-31, Asia/Seoul. **이 README는 사용자의 최신 요구와 실제 미완료 상태를 정리한 문서입니다. 이전 문서의 ‘완료/정상’ 주장보다 아래 상태와 사용자의 현장 피드백을 우선하세요.**

## 1. 먼저 알아야 할 현재 상태

- 이동약자 사용자가 몸 상태를 자연어로 입력하면 AI가 조건을 추출해 길을 추천하는 MVP입니다. 시연 지역은 월곡역·루나밸리·서울대학교사범대학부설중학교 주변입니다.
- 현재 지도·시설 표시·도로 그래프 경로 계산·Gemini 연결 코드·HTML 시연본은 있습니다. **실제 사용자가 기대하는 현장 경로는 아직 해결되지 않았습니다.**
- 사용자는 휠체어 상태에서 안내된 남쪽 경로를 지적했고, 월곡역·월곡로 쪽으로 돌아야 한다고 설명했습니다. 이후 엔진 수정으로 나온 약 3km 북쪽 우회도 사용자가 ‘그쪽 아니거든’이라고 했습니다. 따라서 **현재 3km 경로를 올바른 길/안전한 길/사용자 승인 경로로 간주하지 마세요.**
- 최신 요구는 ‘가중치나 특정 지점 하드코딩으로 방향을 맞추지 말고, 정밀지도를 실제로 불러와 원인을 고쳐라’입니다.
- **서울 1:1,000 수치지형도(DXF/NGI) 원본은 아직 미확보이고, 로더/가져오기 기능도 미구현입니다.** 공식 제공 경로와 로그인 필요 여부만 확인했습니다. 정밀지도 연동이 된 것으로 보고하지 마세요.
- 포함된 기존 지형 자료는 1:5,000 서울 표고점·등고선, Copernicus DSM, Tilezen 고도입니다. 1:1,000 정밀 원본으로 바꾸어 부르지 마세요.
- 현재 GPS는 선분 매칭·자동 다음 구간·잔여 거리·이탈 확인·수동 재탐색을 제공하는 기술 시연입니다. 자동 재탐색은 실기기 검사 전 기본 보류이며, 실제 회전·출입구 안내 정확성은 아직 현장 검증하지 않았습니다.
- 테스트 통과는 코드와 내장 데이터의 동작 검증입니다. 현장의 휠체어 통행 가능·안전·정확한 보도 연결을 입증하지 않습니다.

## 3. 실행 방법

### 화면만 확인

`동행길-전달용.html`을 최신 Chrome으로 엽니다. 내장 지도·시설·기기 내 문장 규칙·경로 계산이 동작합니다. **파일 단독 실행은 실제 Gemini AI를 호출하지 않습니다.** 화면에 기기 내 해석/AI 서버 미연결이 표시돼야 합니다.

### OSM 타일 지도 시연 (Windows)

`동행길-실행.cmd`를 더블클릭하면 로컬 서버와 Chrome(없으면 기본 브라우저)이 열립니다. 인터넷 연결 시 OSM 표준 타일을 Leaflet으로 표시하며, 기존 Gemini 설정을 서버에서 읽습니다. 실행 창을 닫으면 서버도 종료됩니다.

배경을 이중으로 그리던 서울 전체 캔버스/학교 주변 별도 렌더러를 제거했습니다. 드래그·확대·축소는 Leaflet 타일 레이어가 처리합니다. 연결 실패 시 내장 OSM 자료를 같은 Leaflet GridLayer로 표시하고 지도 상태와 다시 연결 버튼을 보여 줍니다. 파일을 직접 열 때는 내장 지도만 사용합니다. OSM 타일 요청에는 정상적인 웹 Referer가 필요하므로 온라인 시연은 위 실행 파일을 이용하세요. 타일을 미리 다운로드하거나 파일에 묶지 않습니다.

배경 타일은 경로 계산용 도로망이나 정밀 1:1,000 자료를 갱신하지 않습니다. 기존 경로·시설·AI 기능과 현장 미검증 한계는 그대로 적용됩니다.

### 서버와 실제 AI

Node.js 18 이상(기존 확인 환경 Node 22)을 준비하고 이 README가 있는 폴더에서 실행합니다.

```sh
node donghaeng-nav/scripts/launch.mjs
```

macOS에서는 `동행길-실행.command`를 열어도 됩니다. 4173번부터 비어 있는 포트를 찾고 실제 접속 URL을 출력합니다. 키가 없으면 Chrome의 `/setup`에서 사용자가 본인 Gemini 키를 입력합니다. 터미널/채팅에 키를 붙여넣지 않습니다. 실행 창을 닫으면 서버도 종료됩니다.

```sh
node donghaeng-nav/scripts/launch.mjs --no-open
```

브라우저 자동 실행 없이 시작할 수도 있습니다. `node server.mjs`는 고정 설정 포트를 사용하므로 포트 충돌 시 위 launcher를 권장합니다.

실행 주소가 `http://127.0.0.1:4173`이라면:

- `/` — 실제 최종 HTML
- `/app/` — 분리된 개발 소스 화면
- `/setup` — 로컬 API 키 설정
- `/?demo=luna-wheelchair` — 루나밸리 서측 경계에서 학교 대표점까지 자동 시연. **현재 문제를 재현하기 위한 프리셋이며 올바른 길을 증명하는 프리셋이 아닙니다.**

기본 모델은 코드에 `gemini-3.5-flash-lite`로 설정돼 있습니다. 기존 개발 환경에서 실제 응답을 확인한 이력은 있지만, 받는 사람의 키·쿼터·모델 접근 가능 여부는 새로 확인해야 합니다. 기존 `gemini-2.5-flash-lite`는 당시 생성 요청에서 이용 불가 404를 반환했습니다. 키를 HTML/클라이언트에 넣지 마세요.

## 4. 반드시 유지할 UX와 기능

- 사용자는 **상태 문장 + 출발/목적지 + 길 찾기 한 번**으로 이용합니다. 계단/경사/휴식 조건 체크박스, AI 켜기 체크박스, 별도 ‘AI 해석’ 버튼을 다시 만들지 마세요.
- AI는 상태에서 이동 요구·부정 표현·휠체어·휴식 선호를 추출합니다. 경로 좌표·존재하지 않는 벤치·경사·출입구를 생성하지 않습니다. 경로는 검증 가능한 지도 그래프에서 계산해야 합니다.
- 위치·목적지·지도 데이터는 현재 AI로 보내지 않습니다. 서버에는 상태 문장만 보냅니다. 이 경계를 유지하세요.
- AI 연결 실패와 파일 단독 실행은 기기 내 규칙이라고 명확히 표시합니다. 실제 AI 성공으로 위장하지 않습니다. 입력 수정 시 오래된 응답을 버리고, 실패한 요청은 다음 제출에서 재시도합니다.
- 지도 검색·출발/목적지 핀·시설 개별/전체 ON/OFF·팝업·이동 순서·경로 저장·모바일·오프라인 표시를 유지하세요.
- 시설 ON/OFF는 **표시만** 바꾸며 경로 계산 조건에는 영향을 주지 않습니다. 이 토글을 경로 조건 체크박스와 혼동하지 마세요.
- 시설 데이터는 이미 여러 번 확대됐습니다. 과거의 67/168개만 있는 버전으로 되돌리지 마세요. 현재 집계/근거는 데이터와 최종 빌드 manifest에서 다시 읽으세요. 원본 ID 중복과 좌표 없는 후보를 주의하세요.
- 외부 배포는 하지 않습니다. 현재 사용자는 로컬 Chrome·HTML 시연을 원합니다.

## 5. 우선 과제 A — 1:1,000 정밀지도 실제 확보와 연동

### 공식 확보 경로

서울시 공식 안내: https://news.seoul.go.kr/gov/archives/528208

이 안내는 서울 1:1,000 수치지형도 v1.0(DXF), v2.0(NGI)를 국토정보플랫폼에서 제공하며 다운로드 시 로그인이 필요하다고 명시합니다.

국토정보플랫폼: https://map.ngii.go.kr/
지도 화면: https://map.ngii.go.kr/ms/map/NlipMap.do?

기존 조사에서 쿼리 없는 지도 주소가 HTTP 400을 반환하는 경우가 있었고, 공식 진입점 및 위 `?` 주소는 HTTP 200으로 열렸습니다. 로그인·본인 인증이 필요하면 사용자가 공식 사이트에서 직접 해야 합니다. 비밀번호를 채팅으로 요구하거나 다른 사이트의 공개 스크립트 키를 빼서 쓰지 마세요. 이 폴더에 로그인 세션은 없습니다.

### 해야 할 실제 작업

1. 월곡역·루나밸리·학교를 덮는 도엽을 공식 플랫폼에서 확인하고 원본을 확보합니다. 조사/제작일, 도엽번호, 축척, 좌표계, 수직 기준, 이용조건을 기록합니다. 원본과 해시를 보존합니다.
2. DXF/NGI/SHP 등 실제 포맷을 읽어 WGS84 GeoJSON 등 런타임 포맷으로 변환하는 **실제 로더**를 구현합니다. 좌표계를 이름만 보고 임의로 가정하지 마세요. 잘못된 좌표계, 범위 밖 자료, 빈 파일, 오류를 처리합니다.
3. 정밀 원본의 도로·보도·횡단보도·계단·교량·지하/층위·출입구 등 제공되는 지물과 속성을 먼저 확인합니다. 없는 지물을 만들어내지 않습니다.
4. 정밀 레이어를 지도에 표시해 기존 OSM과 위치·연결을 대조합니다. 지도 배경만 고해상도로 교체하고 경로 계산까지 개선됐다고 보고하지 마세요.
5. 실제 보행 가능한 연결망을 구성/보정합니다. 도로 경계선·차도 중심선·건물 폴리곤을 그대로 보행 경로라고 취급하지 않습니다. 교차해 보이는 선도 높이/층위가 다르면 연결하지 않습니다. 사유지·차도·계단·폐쇄 지점·출입구 접근 제한을 처리합니다.
6. 학교 건물 중심점이 아니라 **근거가 있는 보행 출입구**로 안내해야 합니다. 현재 출발 프리셋은 루나밸리 서측 경계점이고 출입구 확인이 아닙니다. 현재 학교 대표점→도로 연결 약 98m도 미검증입니다.
7. 원본을 아직 못 받으면 ‘정밀지도 미연결’을 정확히 표시하고, 확보에 필요한 사용자 작업만 구체적으로 설명하세요. 다운로드/불러오기/경로 연동을 각각 구분해 완료 여부를 보고합니다.

단순 도엽 배경 표시, 선을 예쁘게 그리기, 고도 타일 보간은 보행 네트워크 정밀화와 다릅니다. 이 과제의 목표는 사용자가 실제로 다니는 길과 연결이 맞는 지도를 경로 엔진에 사용하는 것입니다.

## 6. 우선 과제 B — 경사·접근성 데이터 검증과 경로 계산

- OSM 등록 경사, 원래 Tilezen 추정, 주변 지형 보완 추정, 자료 차이, 실측 경사, 미확인을 분리합니다.
- 서울 표고점/등고선은 보도 노면 실측 경사가 아닙니다. Copernicus는 건물·수목이 포함될 수 있는 DSM입니다. 어느 자료도 휠체어 통행 가능을 확정하는 데 쓰지 않습니다.
- 경사(%)는 높이 차/수평거리×100입니다. 보도 노면 실측 또는 신뢰할 수 있는 구간 자료가 없으면 짧은 구간을 정밀 측정한 것처럼 표시하지 않습니다. 지지거리·해상도·자료 시점·좌표계·수직 기준을 함께 보존합니다.
- 교량·고가·터널·지하보도 등에 지표 고도를 그대로 적용하지 않습니다. 결측을 0%로 채우지 않습니다. 자료가 크게 다르면 차이와 불확실성을 남깁니다.
- 현재 5%는 제품 추천 회피 정책값입니다. 법적/보편적 안전 기준이 아니고 실제 노면 경사 상한 보장도 아닙니다.
- 실제 길이 잘못 나오는 원인을 연결망, 층위, 스냅 지점, 출입구, 보행 가능 속성, 경사 자료, 비용 함수로 나누어 조사하세요. 원하는 방향이 나올 때까지 상수를 조정하지 마세요.
- 특정 지명·도로 ID·‘북쪽 좌표’·강제 경유지로 사용자 예시만 맞추지 마세요. AI가 ‘북쪽으로’ 생성한 좌표도 근거 없이 사용하지 않습니다.
- 휴식 경유는 이동 제약을 깨지 않아야 합니다. 거주자 전용 아파트 벤치, 대표 좌표/추정 위치, 현재 폐쇄/운영시간 밖 쉼터를 자동 이용 가능 지점으로 간주하지 않습니다.

현재 엔진에는 미확인 구조물이 최대 경사 비교에서 빠지는 오류를 고친 이력이 있습니다. `unresolvedSurfaceMeters`를 우선 줄이고 그 안에서 최대 참고 경사/이동 부담을 비교합니다. 그러나 이 방식의 약 3km 결과는 사용자가 원하는 실제 길과 맞지 않았습니다. **이 정책을 무조건 정답으로 유지하라는 뜻이 아닙니다. 정밀자료로 원인을 검증하고 바꿀 근거를 제시하세요.**

## 7. 우선 과제 C — 실제 내비게이션 기능

초기 `startTracking()`의 최근접 노드 방식은 새 내비게이션 세션으로 교체했습니다. 현재 구현·보류 상태는 [내비게이션 구현 현황](donghaeng-nav/docs/navigation-implementation.md)을 우선합니다. 아래는 초기 요구 목록이며, 구현 여부와 현장 검증 완료는 구분합니다. 상세 화면의 ‘시뮬레이션’과 ‘경로 GPS 재생’은 실제 이동 확인이 아닙니다.

구현/보강할 항목:

- GPS 정확도·권한 거부·신호 유실 상태 처리, 위치 핀과 출발점 보정.
- 보행 도로 선분 기준의 지도 매칭. 단순 최근접 노드로 다른 보도/차도/교량·지하 경로에 붙지 않도록 처리.
- 실제 진행 위치에 따른 다음 구간·회전·횡단·남은 거리/시간 안내. 진행도는 점프/역주행/오차를 고려.
- 지속적이고 신뢰할 수 있는 이탈을 감지해 **같은 접근성 조건**으로 재탐색. GPS 한 번 튀는 값으로 반복 재탐색하지 않기.
- 실제 출입구 접근과 도착 판단. 건물 중심에 가까워졌다고 도착 처리하지 않기.
- 휴식 장소 도착/지나침·휴식 경유 실패·운영 미확인 표시.
- 모바일 화면에서 다음 행동이 우선 보이고 지도·안내·시설 제어가 서로 가리지 않도록 하기.
- 시뮬레이션·GPS 실제 이동·위험 검토 대안을 명확히 구분하기. 독립 이동 불가/미확인 대안을 정상적인 휠체어 실시간 안내처럼 제시하지 않기.

음성/진동 등 추가 기능보다 실제 길·경사·보도 연결·진행도 정확도를 먼저 해결하세요.

## 9. 빌드·검증 방법과 주의점

폴더 최상위에서:

```sh
python3 donghaeng-nav/scripts/build-html.py
```

최상위 `동행길-최종.html`과 `동행길-시연.html`을 함께 만듭니다. 전달용 이름도 최신으로 맞추려면 다음을 실행합니다.

```sh
cp 동행길-최종.html 동행길-전달용.html
```

지도/경로 엔진/전처리 입력은 GIS 비교 검증의 SHA-256에 묶여 있습니다. `engine.js`나 관련 입력을 바꾸고 빌드가 ‘검증 입력이 바뀌었습니다’로 실패하면 **해시 체크를 지우지 말고 재검증**하세요. 재검증이 실제 지형 정확도를 보장하는 것은 아닙니다.

```sh
python3 -m venv .venv-gis
.venv-gis/bin/python -m pip install -r donghaeng-nav/requirements-terrain-review.txt
.venv-gis/bin/python donghaeng-nav/scripts/review-terrain.py
python3 donghaeng-nav/scripts/build-html.py
```

GIS 의존성 설치에는 네트워크가 필요합니다. 기존 작성 환경의 `/private/tmp/...` 가상환경은 전달하지 않았습니다. DXF/NGI 로더에 필요한 라이브러리·지원 드라이버도 실제 사용 환경에서 확인하세요.

코드 변경에 맞는 검증을 고르되 최소한 다음 핵심 검증을 읽고 필요한 검사를 실행하세요.

```sh
node donghaeng-nav/scripts/test-condition-api.mjs
node donghaeng-nav/scripts/test-routing-uncertainty.cjs
node donghaeng-nav/scripts/test-terrain-screening.cjs
node donghaeng-nav/scripts/test-terrain-review.cjs
node donghaeng-nav/scripts/test-auto-routing.cjs
node donghaeng-nav/scripts/test-auto-plan-ui.cjs
node donghaeng-nav/scripts/test-terrain-screening-ui.cjs
node donghaeng-nav/scripts/test-final-ui.cjs
```

브라우저 검증은 Playwright와 Chrome이 필요합니다. 이 환경에 없으면 별도 설치합니다. 일부 스크립트는 작성자의 Codex 캐시 경로를 fallback으로 포함하지만 전달 환경에 있다고 가정하면 안 됩니다. 표준 `playwright` 패키지가 있으면 그쪽을 우선 사용하며, 일부 스크립트의 캐시 경로는 정리할 필요가 있습니다. Chrome 경로도 플랫폼에 맞게 설정/수정하세요.

실제 GIS 원본을 바꾼 뒤에는 합성 테스트만으로 끝내지 말고 실제 월곡역·루나밸리·학교 도로망, 서로 다른 출발점·목적지·휠체어/휴식 요청, 모바일, 실제/모의 GPS를 검사합니다. 정답 경로를 코드에 넣어 테스트를 통과시키지 마세요.

## 11. 다음 Codex에게 그대로 전달할 요청

> README.md와 AGENTS.md를 먼저 읽어라. 이 프로젝트의 현재 경로는 현장 정답으로 검증되지 않았고 사용자가 남쪽 경로와 약 3km 북쪽 경로를 모두 지적했다. 계획 설명만 하지 말고 실제 1:1,000 정밀지도 원본 확보/로더/보행 연결 검증부터 진행하라. 공식 다운로드의 사용자 로그인만 필요하면 그 이유와 필요한 작업을 구체적으로 설명하라. 원본이 없는데 확보했다고 말하거나, 지명·북쪽 좌표·고정 경유지로 예시만 맞추지 마라. 정확한 지도·접근성 데이터를 경로 엔진에 연결하고, 상태 문장 AI 해석을 유지한 채 휠체어 경사·휴식 요구와 실제 GPS 내비게이션을 구현하라. 단일 HTML과 서버 실행본을 함께 갱신하고 검증 결과/한계를 보고하라. API 키를 포함하거나 외부 배포하지 마라.
