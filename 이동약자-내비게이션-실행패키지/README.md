# 이동약자를 위한 내비게이션

**2026-11-04 실행 패키지.** 짧은 화면 이름은 **이동약자 내비게이션**입니다. 월곡역·루나밸리·서울사대부중 주변에서 사용자의 상태 문장에 맞춰 경로와 휴식 장소를 찾는 MVP입니다.

## 파일

| 파일 | 용도 |
| --- | --- |
| `휴대폰용.html` | 휴대폰의 HTML 실행 브라우저에서 열기 |
| `컴퓨터용.html` | PC·Mac의 Chrome/Edge에서 열기 |
| `검증결과.json` | 자동 검사 결과와 검사 범위 |
| `SHA256SUMS.txt` | 파일 무결성 확인용 해시 |

두 HTML의 내용은 같은 최신 빌드이며 화면 크기에 따라 모바일·PC UI가 바뀝니다. 지도·시설·지형 참고 자료·경로 계산 코드를 파일 안에 넣었으므로 설치나 PC 서버가 필요하지 않습니다. 원본 조사 자료 전체와 개발용 폴더를 전달하는 패키지는 아닙니다. 기존 저장소의 소스/연구 자료를 덮어쓰지 않습니다.

## 실행 방법

GitHub의 HTML 파일 화면은 실행 화면이 아니라 소스 보기입니다. **파일을 다운로드한 다음 브라우저로 여세요.** 저장소의 `Code → Download ZIP`으로 받아 압축을 풀어도 됩니다.

1. PC는 `컴퓨터용.html`, 휴대폰은 `휴대폰용.html`을 브라우저로 엽니다.
2. **AI 키 입력**을 눌러 본인의 Gemini API 키만 붙여넣고 **이 창에서 사용**을 누릅니다.
3. 출발·목적지를 정하고 상태를 입력합니다. 예: “휠체어를 이용해요”, “무릎이 아파 중간에 벤치에서 쉬고 싶어요.”
4. **내 상태에 맞는 길 찾기**를 누릅니다.
5. 시간·거리·경로를 비교하고 **이동 순서 보기** 또는 **경로 재생**을 선택합니다.

AI에는 인터넷과 유효한 Gemini 키·사용 가능한 할당량이 필요합니다. 키가 없거나 호출이 실패하면 기기 내 문장 규칙으로 계산하며 화면에 구별해 표시합니다. **‘Gemini 해석’일 때 실제 AI 응답을 사용한 것입니다.** 키 입력 완료 자체는 실제 연결 성공을 뜻하지 않습니다.

키는 Google Gemini API에 직접 전송하고 현재 창 메모리에서만 사용합니다. 위치·목적지는 AI에 보내지 않습니다. HTML·브라우저 저장소에 키를 저장하지 않으며 새로고침/창 종료 후 다시 입력해야 합니다. **키가 들어간 별도 파일이나 `.env`는 이 패키지에 없습니다.**

### 휴대폰에서 열리지 않을 때

파일 앱의 단순 미리보기와 HTML 실행 브라우저는 다릅니다. JavaScript 실행을 지원하는 브라우저로 열어야 합니다. Android의 `file:`/`content:` 분기를 지원하도록 만들었지만 실제 Android/iPhone 파일 앱에서는 아직 검증하지 않았습니다. 특히 iPhone 파일 미리보기에서 모든 기능이 된다고 보장하지 않습니다.

### GPS 안내

일반 경로의 **안내 시작**은 위치 권한이 허용된 브라우저에서 다음 방향·회전까지 거리·남은 시간/거리를 갱신합니다. GPS 신호가 나쁘면 자동 진행을 보류하고, 신호가 복구되면 다시 갱신합니다. 위치 권한 거부·이탈·도착·일시정지/종료를 처리합니다.

파일에서 실제 GPS가 가능한지는 브라우저의 보안 출처 정책에 따라 다릅니다. **키 입력으로 GPS 제한이 해제되지는 않습니다.** 현재 승강기 접근 연결을 가정한 육교 경로는 미리보기/재생으로 제공하며 실제 GPS 시작은 제한합니다. 파일 단독으로 안 되는 GPS·온라인 타일을 쓰려면 별도 HTTP(S) 실행 환경을 준비해야 합니다.

## 이번 버전에 반영한 작업

- 서비스 이름을 정식/짧은 이름으로 통일하고 모바일 하단 패널·지도 중심 UI, 경로 카드와 설명 펼치기를 정리했습니다.
- 상태 문장을 한 번 입력하면 Gemini가 휠체어·계단/경사 부담·벤치/쉼터·휴식 간격·거리 우선 조건을 추출하고, 실제 내장 도로망에서 길을 계산합니다. AI가 도로나 좌표를 만들어내지는 않습니다.
- 시설 종류별/전체 ON·OFF, 팝업, 데이터 출처/시점/현장 미확인 표시, 지도 검색·경로 저장·이동 순서를 유지했습니다. 표시 토글은 경로 조건을 바꾸지 않습니다.
- 공식 1:1,000 수치지형도 DXF 16도엽을 변환해 인도·도로·건물·등고선/표고점 검토 레이어를 연결했습니다. 확인한 분류 16,169개입니다. 경계선을 그대로 보행 중심선으로 쓰지 않습니다.
- 출발·도착을 가까운 도로 선분에 연결하고, 학교는 포르티시모 인근의 학교 앞 도로를 기준점으로 안내합니다. 실제 출입문 좌표를 확인한 것은 아닙니다.
- 지상 도로가 NGII/OSM 건물 내부와 겹치는 구간을 계산에서 제외했습니다. 원본 그래프는 보존하며 지도 레이어를 꺼도 검사합니다. 단지 내부 재현 검사에서 새 본 경로의 건물 겹침0을 확인했습니다.
- 양쪽 승강기 존재에 대한 사용자 설명을 육교 경로 검토에 반영했습니다. 승강기 문 위치·접속 동선·현재 운행을 측량/실시간 확인한 것은 아니므로 연결 점선은 예시입니다.
- GPS 선분 매칭에 따라 지도 위 방향 배너·다음 행동·남은 거리/시간, 추적 복귀, 휴식/도착 확인과 경로 재생을 구현했습니다. 일시 수신 실패는 새 위치를 기다려 복구하며 권한 거부는 종료합니다.
- 파일 안에서 키를 입력해 Google에 직접 연결하는 모드를 추가했습니다. 실패·잘못된 응답은 실제 AI 성공으로 위장하지 않고 기기 내 해석으로 구분합니다.

## 검증한 내용

- 모바일 크기의 Chrome 단독 HTML: 키 형식·입력/삭제·메모리 사용·리로드 초기화, 요청에는 상태 문장만 포함, 성공 캐시·403/응답 형식 실패·재시도, 실제 내장 도로 경로 계산, 브라우저 오류0.
- 기존 AI/벤치·쉼터·시설 토글·저장/모바일·오프라인 흐름, 경로 중간 건물 겹침 재현/제외.
- 모의 GPS: 좌·우 회전까지 거리, 진행에 따른 다음 행동, 정확도 저하·신호 끊김·이탈·일시정지/종료·재생·잔여 거리 갱신.
- 실제 Google API에 키 없는 OPTIONS 요청으로 파일 출처(`Origin: null`)·필요 헤더 허용을 확인했습니다.

**자동 AI 검사는 가짜 시험 키와 모의 응답을 사용했습니다. 본인 키의 실제 생성 응답, 실제 휴대폰 파일 앱, 현장 GPS 이동은 아직 검증하지 않았습니다.** 상세는 `검증결과.json`을 참고하세요. 모의 검사를 물리 현장 안전 검증으로 해석하지 마세요.

## 남은 작업과 데이터 한계

지형 고도 추정과 OSM 등록값·자료 차이·경사 미확인을 구별합니다. 서울 표고점·등고선이나 Copernicus DSM은 보도 노면 실측 경사가 아닙니다. 건물 겹침0과 경로 표시가 휠체어 통행 가능을 확정하지 않습니다. 실제 단지 출입구·학교 보도 편·턱/폭·승강기 문/운행·정확한 횡단보도 연결·물리 GPS 검증이 남아 있습니다. 예전에 나온 약3km 우회를 현장 정답으로 간주하지 않습니다.
