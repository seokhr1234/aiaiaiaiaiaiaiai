# 월곡역 경사·고도 자료 검토와 적용 결과 · 2026-10-31

## 결정

**서울시·Copernicus 값으로 직접 대체한 경로 구간은 0개입니다.** 노면 높이·수직기준·개별 관측 정확도·지역 검증이 부족하여 기존보다 정확하다고 입증되지 않았습니다. 원본과 Tilezen 고도·경사 수치는 그대로 보존하고, 새 자료는 비교·불확실성 표시에 사용했습니다. 자료 차이가 크거나 구조물인 구간은 지형 추정을 노면 경사로 사용하지 않습니다. 실제 보도 통행 안전성 개선을 입증한 결과가 아닙니다.

## 읽고 확인한 자료

요청한 research/README.md, sources.csv와 derived 전체를 읽고 raw ZIP·TIFF, 기존 지형 타일과 경로 엔진을 대조했습니다. 조사 범위는 경도 127.018~127.065 / 위도 37.580~37.621의 사각형이며 약 18.89km²입니다. 정확한 반경 2km 원형이 아닙니다. 원본은 읽기만 했고 모든 입력 SHA-256은 validation-report.json에 기록했습니다.

| 자료 | 실제 확인 | 채택하지 않은 이유 |
|---|---|---|
| 서울 2025 제공 표고점 | 1,058개 원본 UFID·HEIGHT·변환 위치 일치. 기존 Tilezen 범위 내 665개 | 노면점인지, 수직기준과 개별 정확도 미확인 |
| 서울 등고선 | 파생 228건의 HEIGHT가 원본과 일치 | 지형 등고선이며 보도 노면 측정 아님. 도로 방향의 지지 거리·수직기준 확인 필요 |
| 서울 2023 제공 원본 | PRJ·아카이브 보존, 같은 사각형에 정확히 포함되는 표고점 1,061개 | 2025 제공본과 공통 UFID 0개. 단순 ID 차이를 지형 변화·정확도 개선으로 해석하지 않음 |
| Copernicus GLO-30 | 148×169 native crop, 원본 픽셀과 affine 모두 일치 | DSM의 건물·수목·인프라 영향, 노면 분리·지역 실측 검증 없음 |
| 기존 Tilezen | 원본 타일·고도·17,697개 추정 연결값 보존 | 원시 DEM 실효 해상도·지역 정확도·노면 고도 미검증. 참고 비용에만 사용 |

서울 원본 PRJ는 EPSG:5174(Bessel/Korean 1985)이며 수평 단위는 m입니다. 기존 파생 GeoJSON의 경위도는 원본을 EPSG:4326으로 변환한 위치와 수치적으로 일치했습니다. PROJ 변환에 선언된 1m 정확도는 현지 기준점 대조 결과가 아닙니다. HEIGHT는 m로 해석했으나 수직기준과 실제 관측 방법은 확인되지 않았습니다. 공식 제공 페이지의 2023년 기준, 2025-03-20 갱신일, XML의 생성·복사 시각을 개별 측정일로 취급하지 않았습니다.

Copernicus 수평 좌표는 EPSG:4326, 제품 수직 기준은 EGM2008(EPSG:3855), 표고 단위는 m입니다. 이 위치의 원본 격자 간격은 동서 24.53m × 남북 30.83m입니다. 해상도나 제품의 LE90 규격은 월곡역 보도의 경사 정확도가 아닙니다. 원본 PixelIsPoint 태그가 파생 파일에서는 Area로 바뀐 점도 기록했습니다. 픽셀과 affine 좌표가 동일한 것은 확인했으며 원본을 수정하지 않았습니다.

## 밀도·도로 거리·표면 검증

표고점 밀도는 약 56.0개/km², 최근접 점 간격 중앙값 79.4m, 90백분위 135.5m입니다. 일정 격자가 아닙니다. 점에서 현재 도로망 선형까지 거리 중앙값은 4.84m이며, 5m 이내 533개·10m 이내 580개입니다. 조사지역이 도로망 범위보다 넓어 외곽 점들의 거리가 크며 전체 사각형 통계라는 점을 유의해야 합니다. 2차원으로 가깝다는 사실만으로 차도·보도·옥상·교량 상면을 구분할 수 없습니다.

기존 OSM 건물 윤곽과 겹치는 점은 7개였지만 건물 지도의 범위·완전성은 검증되지 않았습니다. 나머지가 맨땅이라고 판정하지 않았고 수목 영향도 확인하지 못했습니다. 실제 보도 점임을 확인할 현장 기준점·토지피복·층위 자료가 필요합니다.

## 같은 도로에서의 비교

도로를 따라 수평 거리 100m 창을 사용하고, Copernicus 원본 셀 3개 이상을 통과하는 경우만 비교했습니다. 두 래스터는 모두 쌍선형 표본화로 비교하고, 서울 표고점은 100m 안의 삼각형 지지가 있는 경우에만 선형 보간을 **진단용**으로 계산했습니다. 등고선의 교차 높이는 기록하지만 노면 경사로 변환하지 않았습니다. 방법은 Δ고도 / 도로를 따른 수평거리 ×100입니다. 창 평균은 짧은 급경사나 턱을 놓칩니다. Tilezen 기존 30~60m 창을 새 자료의 고정밀 노면값으로 승격하지 않습니다.

비교 가능한 연결 레코드 11,085개에서 Tilezen–Copernicus 경사 차이 중앙값은 2.62%p, 90백분위 7.55%p였습니다. 이들은 인접 창이 겹치는 연결 레코드이며 독립 관측 표본 11,085개를 뜻하지 않습니다. 같은 위치에서 서울 표고점과 래스터 높이도 비교했지만 그 차이는 정확도 오차가 아닙니다. 수직기준·표면·시기·처리 방법이 달라 어느 쪽도 정답으로 선택하거나 편향을 강제로 보정하지 않았습니다.

불일치 검토 정책의 민감도: 2%p: 6,622개 / 3%p: 4,859개 / 5%p: 2,461개 / 8%p: 954개. 2%p 이상은 차이를 기록하고, 5%p 이상은 참고 추정을 경로에서 제외해 경사 미확인으로 처리합니다. **5%p는 검토 대상을 선별하는 보수적 정책값이며 측정 정확도·위험 한계·통계적 신뢰구간이 아닙니다.**

## 실제 구현

- 현재 도로망 4,463개 way / 중복 제거 연결 21,553개를 검토했습니다.
- 기존 참고 추정 유지 14,553개, 수치 미확인 3,872개, 자료 차이 2,461개, 지형 적용 부적합 667개로 기록했습니다. OSM 수치 표기는 별도 원천으로 보존합니다.
- 교량·고가·터널·지하 location/layer·층위·실내·덮인 동선·계단·노드의 지하 표기를 구별합니다. 통행을 일괄 금지하지 않고 지표 고도의 적용만 제외합니다.
- 자료 차이로 추정을 미확인 처리할 때 비용이 더 낮아지는 지름길이 되지 않도록 기존 부담과 미확인 부담 중 낮지 않은 값을 유지합니다. 구조물에는 부적합한 지표 고도를 재적용하지 않습니다.
- `incline=up/down/yes`를 숫자 0으로 바꾸지 않습니다. 실제 원본은 up 10개 / down 7개 / 0% 1개 / yes 1개입니다. 도(°)는 tan 변환으로 %와 구별하고, 역방향의 부호를 반전합니다.
- 사용자가 명시한 경사 상한에 대한 기존 추천 회피 규칙은 OSM 수치 표기와 유지된 Tilezen 참고 추정에서 보존합니다. 이는 추천 규칙일 뿐 실제 노면이나 휠체어 통행 가능·불가능의 확정 판정이 아닙니다. 자료 차이로 미확인인 구간이 남으므로 실제 상한 충족을 보장하지 않습니다. 모든 결과의 `wheelchairPassability`는 `unverified`, `slopeLimitGuaranteed`는 false입니다.
- 화면은 OSM 수치·Tilezen 참고 지형 추정·경사 미확인, 자료 차이와 구조물 길이를 구별합니다. ‘자료 차이·출처 보기’에서 비교 창·부호·자료 한계와 이용조건을 확인할 수 있습니다.
- 원본 도로·시설·조사 입력 및 Tilezen 추정 값은 덮어쓰지 않았습니다. 입력·타일·계산 코드 해시가 바뀌거나 검증 파일이 빠지면 빌드가 오래된 검증을 조용히 적용하지 않습니다. 브라우저에서도 도로망 SHA-256과 지형 자료의 버전을 대조합니다.

## 월곡역 실제 도로망 테스트

월곡역 시연 기준점 → 월곡꿈그림도서관. 거리에는 미검증 연결이 포함됩니다. 쉼터 테스트의 2026-10-30 10:00 KST는 등록 운영시간을 검증하는 고정 시각이며 실제 개방 확인이 아닙니다.

| 조건 | 변경 전 | 변경 후 | 변경 후 참고 추정 길이 | 변경 후 수치 미확인 길이 |
|---|---:|---:|---:|---:|
| short | 351m | 351m | 167m | 165m |
| bench | 431m | 404m | 286m | 77m |
| wheelchair | 380m | 383m | 286m | 77m |
| limit | 463m | 434m | 304m | 98m |

거리 우선 경로의 도형은 유지됐습니다. 다른 조건의 경로가 바뀐 것은 불확실한 구간을 별도로 처리한 결과이며, 새 자료가 실제로 더 정확하거나 물리적으로 더 안전하다는 증거가 아닙니다. 등록 계단 제외·휴식 경유와 기존 시설 기능도 테스트합니다. 자세한 결과는 `docs/terrain-review-route-tests.json`, 브라우저 검증은 `docs/terrain-review-ui-tests.json`에 있습니다.

## 추가 확인할 구간과 자료

`needs-validation.geojson`과 `road-review.csv`에 OSM way ID·연결 ID·좌표·이유·같은 창의 원천별 추정치를 기록했습니다. 먼저 자료 차이가 큰 구간과 역 주변 이용 경로를 현장 검증해야 합니다. 필요한 것은 구간별 종단·횡단 경사, 측정 위치·일자·정확도, 보도/차도·교량/지하 구분, 수직기준과 재배포 허락입니다. 높은 점 밀도나 두 DEM의 일치만으로 노면 검증을 대체할 수 없습니다.

## 재현

일반 실행·HTML 빌드는 GIS 패키지나 네트워크를 요구하지 않습니다. 사전 검증 결과와 해시를 확인합니다.

```sh
# donghaeng-nav 폴더에서
python3 scripts/build-html.py
node scripts/test-terrain-review.cjs
python3 scripts/test-terrain-review-policy.py
node scripts/test-terrain-review-ui.cjs
```

자료 자체를 다시 분석할 때만 `requirements-terrain-review.txt`의 GIS 패키지를 설치한 Python으로 `scripts/review-terrain.py`를 실행하세요. 이번 검증에는 기존 `/private/tmp/terrain-gis-venv/bin/python`을 재사용했습니다. 외부 신청·결제·배포는 하지 않았습니다.

## 코드와 산출물 위치

- `scripts/review-terrain.py`: GIS 원본·격자·점 밀도·자료 차이 분석.
- `scripts/terrain-review-policy.py`, `scripts/prepare-terrain.py`: 입력 해시 검증과 원본 추정치 보존.
- `dist/engine.js`: OSM 단위·방향, 구조물 처리, 자료 차이 미확인 및 불확실성 비용.
- `dist/app.js`, `dist/style.css`: 출처 구분·자료 차이·이용조건 안내.
- `scripts/build-html.py`: 검증 결과를 내장한 최종/시연 HTML 생성.
- `data/terrain/review/validation-report.json`, `road-review.json`, `road-review.csv`, `needs-validation.geojson`: 수치 검증과 추가 확인 구간.
- `docs/terrain-review-route-tests.json`, `terrain-review-ui-tests.json`: 실제 도로망·브라우저 검증 결과.
