  대중교통 조회 전에 ODsay로 좌표를 보내는 사실을 표시한다.
- 노선 번호/역·정류장명, 승하차 순서, 환승 횟수, 업체 예상 시간·참고 요금을

  경로 기하가 없어 직선 노선을 만들지 않는다. 같은 좌표에 묶인 기록도 실제 환승
  접속으로 확정하지 않는다. 메인과 확장 화면이 같은 표시 모듈을 사용한다.
- 취소·조건/위치/모드 변경·늦은 응답·빈 결과·손상/업체 오류를 처리한다.

## 실제 ODsay 검사는 실패

설정 확인과 실제 검색을 구분한다. 공개 시청→강남 좌표의 검색은 **총2회**이며
두 번 모두 HTTP502였다. 안전 진단 배포 후 두 번째 응답은
`transit_provider_error`, `providerCode: "500"`, `providerReason: "authorization"`였다.
후보 수신·실제 인증 성공을 확인하지 못했다.

`authorization`은 업체 메시지의 인증 관련 표현을 고정 범주로 바꾼 값이다.
숫자500만으로 키 종류·허용 IP/도메인·서비스 권한 중 정확한 원인을 확정하지 않는다.
업체 원문 메시지/URL/키/전체 노선 응답은 보관하지 않았고 추가 자동 재시도는 없다.
[최소 실제 검색 기록](transit-live-2026-11-14.json).

ODsay 계정에 접근할 수 있을 때 다음을 확인한다. 지금 사용자에게 추가 질문하지 않는다.

1. 해당 앱/키에 `searchPubTransPathT` API 이용 권한과 활성 상태가 있는지 확인.
2. 키 플랫폼이 서버 호출 방식에 맞는지, 실제 배포의 허용 서버/IP/URI 설정과
   일치하는지 확인. 플랫폼 제한을 우회할 Referer를 임의로 만들지 않는다.
3. 변경이 필요하면 Vercel 프로젝트의 Production/Preview 환경에 적용·재배포한 뒤
   상태 GET과 공개 좌표1쌍의 실제 검색을 다시 구분해서 검사한다. 키는 공유하지 않는다.

공식 참조: [ODsay 플랫폼/키 안내](https://lab.odsay.com/guide/guide),
[API 참조](https://lab.odsay.com/guide/releaseReference#searchPubTransPathT).
조회일은 11월14일이며 업체 자료 자체의 갱신 기준일은 확인하지 못했다.
입력은 경위도 좌표이며 위치/역내 연결의 현장 검증은 없다.

## 검증 범위·남은 작업

정상/결측/오류·키 비노출·조건 보존 핵심 검사, 메인/단일 HTML 모의 UI와 기존
도보·확장·API 회귀11개 보고서가 통과했다.
[무결성 검사](transit-release-integrity.json)에서 기존 원본9개·연구·이전 이력·
서울/검토 자산5개를 보존하고 동일 빌드 HTML5개를 확인했다.

공개 Chromium 데스크톱·393px에서 새 모드와 무료 상태 조회·도보 복귀·확장 모듈,
페이지 오류0/자체 리소스 실패0/가로 넘침 없음을 확인했다. 이 브라우저 검사에서는
외부 타일·실제 검색/AI 호출을 차단했다. 캡처의 타일 실패 안내는 검사 조건이다.
[데스크톱](transit-public-desktop.png), [모바일](transit-public-mobile.png).
노선/승하차 표시 자체는 모의 응답으로 검사한 결과이며 실제 후보 성공 증거가 아니다.

실제 노선 기하, 정류장/출입구 ID와 같은 조건의 도보 연계, 시간표·막차·실시간·
저상 차량·승강기·반복 휴식·접근성 검증은 미완료다. 참고 후보를 AI 적격 추천이나
GPS 안내로 승격하지 않았다. T4~T9와 마지막 T10 전체 UI 최적화는 계획에 남긴다.
