# 월곡역 최종 시연 가이드

## 현장 준비

노트북 최신 Chrome에서 `동행길-최종.html`을 열고 준비 완료 메시지를 기다립니다. 충전·화면 밝기·브라우저 확대율 100%를 확인하세요. 지도와 경로는 오프라인 실행되며 출처 링크만 인터넷을 사용합니다. 월곡역 시연 기준점은 GPS가 아닙니다. 실외에서 현재 위치 사용을 누르고, GPS 오차와 실제 출입구를 확인해 출발 핀을 조정하세요. 기준점과 다른 위치에서는 거리와 휴식 장소가 달라집니다.

## 90초 발표 흐름

1. **0–15초 · 문제** — “같은 350m라도 누군가에게는 중간에 앉을 곳이 꼭 필요합니다. 동행길은 오늘의 상태를 길에 반영합니다.”
2. **15–30초 · 비교 기준** — ‘30초 비교 시연’에서 ‘짧은 길’을 선택합니다. 월곡역에서 월곡꿈그림도서관까지 같은 출발·목적지로 도로망을 계산합니다.
3. **30–50초 · 핵심 장면** — ‘쉬어 가는 길’을 선택합니다. 무릎·계단·오르막·휴식 조건이 선택되는 것을 보여 줍니다. 일반 경로와 맞춤 경로, 휴식 경유 장소를 비교합니다. ‘발표 모드’로 입력 화면을 접으면 결과와 순서가 함께 보입니다.
4. **50–65초 · 설명 가능성** — ‘휴식 장소 근거 보기’를 누릅니다. 시설 기준 위치, 원본 링크, 촬영일, 현장 미확인 표시를 보여 줍니다. 사진으로 본 의자와 현재 사용 가능한 의자를 구분한다는 점을 설명합니다.
5. **65–80초 · 실행성** — 팝업을 닫고 이동 순서의 ‘다음 구간’을 누릅니다. 지도에서 해당 구간이 강조됩니다. 시설 전체를 꺼도 경로 조건이 바뀌지 않는 것을 보여 줍니다.
6. **80–90초 · 확장성** — 휠체어 조건으로 바꿉니다. “등록된 계단은 제외하고, 모르는 경사·보도 턱·출입구는 모른다고 표시합니다. 현장 검증과 시설 가동 정보를 연결하는 것이 다음 단계입니다.”

## 실패에 대비한 동작

- GPS 권한 거부·수신 실패: 지도에서 출발지를 정하거나 ‘월곡역으로’를 누릅니다. GPS처럼 소개하지 마세요.
- 발표 중 핀·시설 전체 범위가 달라짐: ‘월곡역으로’ 후 비교 시연을 다시 선택합니다.
- 경로가 안 나옴: 데이터 범위 안의 기본 도서관으로 복원합니다. 서울 전체 시설 표시와 지역 도로망 탐색의 범위를 구분하세요.
- 시설 실제 상태가 다름: 현장 상태 미확인임을 설명하고 브라우저 제보 기능으로 기록합니다. 제보는 자동으로 경로에 반영되지 않습니다.

## 심사 질문에 답할 때

기본 문장 해석은 기기 내 규칙이며, 서버에서 Gemini 확인 버튼을 누르면 상태 문장만 전송해 AI로 해석할 수 있습니다. 어느 방식인지 화면에 표시됩니다. AI가 경로를 만들어낸다고 설명하지 마세요. 경로는 실제 OSM 그래프 탐색으로 계산합니다. 시설 데이터에는 실제 점·선·면, 공원/정류장 기준점, 과거 사진 추정점, 단지 경계가 섞여 있으며 팝업에서 근거와 정밀도를 구분합니다. 자동 휴식 경유는 단지 내부·출입 제한·부지 대표점을 제외합니다. 전체 등록 수는 실물 의자 수가 아닙니다. 실시간 시설 고장·보도 턱·폭과 완전한 무장애 통행은 아직 검증되지 않았습니다.

실제 수량과 경로 측정 결과는 `final-build.json`, `final-ui-results.json`에 자동 기록됩니다.
