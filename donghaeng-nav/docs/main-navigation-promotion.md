# 2026-11-04 이동약자 내비게이션 메인 전환

사용자가 더 발전한 이동약자 내비게이션을 메인으로 사용하도록 요청했다. 최신 독립 GPS 따라가기 HTML을 기준으로 코드와 기존 변환 자료를 분리하고, Node·Vercel 기본 소스와 전달 HTML의 빌드 기준을 통일했다.

## 기준과 보존

- 기준 커밋: `7c16922c302bae11f89e009b5744d499dbd80cf1`.
- 기준 파일: 최상위 `유석현유석현.html`(실제 파일명은 Unicode NFD 분해형).
- 기준 SHA-256: `6e510f90d6793d399d327b99889b69c70f3cf0f33ea1f4aedc306b539d3d3b98`.
- 이 파일의 실행 모듈 20개는 내용 그대로 분리했다. 기존 엔진 `engine.js`도 이전 분리 소스와 같다. 초기 데이터 준비 모듈만 HTTP 분리 자료와 압축 내장 자료를 모두 읽도록 교체했다.
- 런타임 자료 8개는 기준 HTML의 JSON과 의미상 같으며 새 자료를 생성하지 않았다. 기존 도로·주변 지물·시설·배경·지형은 보존하고, 정밀 변환본·횡단부 검토·접속 제보 3개를 `dist/data/precision/`로 분리했다. 지형 JSON의 기존 파일 끝 개행은 유지했다.
- 기존 `research/`, 로컬 비밀 설정, 원본 GIS 자료와 이전 최상위 전달 스냅샷 두 파일은 변경하지 않았다.

## 기본 실행 경로

| 경로 | 전환 후 |
| --- | --- |
| Node `/`, `/index.html`, `/app/` | `donghaeng-nav/dist/index.html`의 같은 최신 메인 프로그램 |
| Vercel 기본 화면 | 같은 dist를 정적 제공. `/app` 및 `/app/:path*` 호환 rewrite 추가 |
| 기존 동행길 이름의 HTML 3개 | 같은 최신 프로그램을 묶은 호환 파일명 |
| 실행 패키지 HTML 2개 | 같은 빌더가 생성하는 전달용 복사본 |
| 최상위 유석… HTML 2개 | 이전 전달 스냅샷, 현재 개발 원본은 dist |

Node의 정적 자산 허용 목록에 새 모듈·정밀자료 경로만 추가했다. `/app.js`를 `/app/` 접두사로 오인하던 치환도 수정해 루트 실행에서 앱 스크립트가 정상 제공된다. 기존 비공개 파일/API 보호와 서버 키 설정은 유지했다.

## 포함한 동작

- 정밀 변환본 16,169피처와 OSM 건물 도형을 이용한 겹침 검토, 지상 겹침 경로 제외, 도로 선분 연결, 접속 제보에 기반한 검토 대안.
- 상태 문장만 전송하는 HTTP 서버 AI, 파일 모드에서만 선택 가능한 PortableAI 직접 연결과 기기 내 대체 해석.
- 경로 GPS 안내·재생·다음 행동, 별도의 위치 추적/정확도·신호 상태, 드래그 후 자동 따라가기 정지와 복귀.
- 최근 개편한 이용안내, 시설 표시·검색·경로 저장·모바일 하단 패널과 기존 저장 키.

정밀 경계선과 접속 제보는 검토 자료이며 보행 중심선·실측 출입구·승강기 운행 검증으로 승격하지 않았다. 기존 위치별 예시·검토 동작을 새로 현장 정확성 개선으로 보고하지 않는다.

## 빌드와 무결성

`python3 donghaeng-nav/scripts/build-html.py`는 기존 런타임 스냅샷을 해시로 확인한 뒤 소스의 CSS/JS와 데이터 8개를 단일 HTML 5개로 묶는다. 다섯 HTML은 같은 해시이며 `final-build.json`, 전달 해시, 패키지 SHA256SUMS도 갱신한다.

`runtime-integrity.json`은 데이터 해시와 보호 경로 코드(엔진·선분 연결·건물 겹침·접속 제보)의 해시를 담는다. 도로망 해시는 기존 지형 검토 입력과 비교하고 주변 지물 연결도 확인한다. 정밀 피처의 `field_verified=false`, `routing_eligible=false`를 검사한다. 시험에서 도로 자료와 엔진 입력을 각각 바꿔 제공하면 출력 전에 실패하고 기존 결과물을 보존함을 확인했다.

원본 전처리를 자동 실행하던 이전 빌드 방식은 원본이 없는 이 저장소에서 재현되지 않았다. 이제 원본 GIS 전처리와 검증된 런타임의 포장을 구분한다. 기존 전처리·GIS 검증 스크립트는 보존했으며 새 입력은 독립 검증과 명시적 무결성 갱신이 필요하다. 스냅샷 해시 검사는 원본 DXF/XML·실제 보행면의 재검증을 대체하지 않는다.

- Vercel 핸들러 로컬 모의 검사 7개 묶음 통과. 추가 app rewrite와 API rewrite의 구분 확인. 실제 Vercel 배포는 실행하지 않음.
- 새 `test-main-navigation.cjs`의 8개 묶음 통과. 기본/호환 주소와 모든 앱 자산, 정밀자료 초기화·건물 겹침 처리·모의 AI 성공/실패·모의 GPS 추적/따라가기/중지/권한 거부·재생·모바일·잘못된 JSON의 준비 오류 확인. 브라우저 오류 0건.

- 기본 HTML 3개와 패키지 HTML 2개의 동일성, 반복 빌드 결과와 패키지 해시 일치 확인.

## 남은 한계

실제 휴대폰·사용자 키 Gemini·현장 GPS·시설 운행·턱·폭·출입구·보행면 경사는 이번 전환에서 검증하지 않았다. 관리형 Chromium이 file URL을 차단하므로 단일 HTML도 localhost에서 실행했다. 원본 16도엽의 DXF/XML을 재입수·재변환하지 않았으며 좌표계 추론·수직 기준 미확인 제한도 유지한다. 소스 통합과 실행 기준 전환을 현장 통행 가능성 검증으로 해석하지 않는다.

이번 작업은 로컬 소스·실행 기준 정리이며 커밋·푸시·Vercel 배포는 수행하지 않았다. 기존 `[skip vercel]` 빌드 생략 설정은 유지한다.

## 후속 커밋·푸시 요청과 배포 기본값

사용자가 전환 내용을 커밋·푸시하도록 요청한 뒤, Vercel 배포는 별도 생략 요청이 없으면 기본 허용하도록 명시했다. 이번 게시 커밋에는 배포 생략 표시를 넣지 않으며 연결된 Git 자동 배포를 허용한다. AGENTS와 최상위 README에 이 기본값을 반영했다. `ignoreCommand`는 명시적으로 생략을 요청하는 커밋에만 적용되는 규칙으로 유지한다. 앞의 미게시·미배포 문장은 소스 전환 완료 당시의 기록이다.
