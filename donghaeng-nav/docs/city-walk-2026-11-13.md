# 서울 기본 지도·레이어 정리와 도보 참고 계산

2026-11-13 KST. 사용자 요청: 겹쳐 보이는 지도 레이어를 정리하고 월곡 중심 화면을 서울 전체로 바꾸며, 도보 길찾기도 포함한다. 네이버 API는 사용하지 않는다.

## 화면에서 달라진 점

- 기본 지도는 서울 전체로 열린다. 출발·도착을 미리 월곡으로 지정하지 않는다. 서울 범위에서 지도 클릭·GPS 출발 지정·등록 시설 이름/주소 검색을 사용한다. 검색 대상은 보유 등록 장소이며 일반 주소 전체를 검색하는 서비스는 아니다.
- 사진의 파란색·회색 선은 정밀 원본의 인도/도로 **경계선**이다. 과거에는 자료 로딩만으로 자동 표시됐다. 이제 기본으로 끄며, 사용자가 선택하고 확대 수준 17 이상일 때 현재 화면에 해당하는 도형만 그린다. 표시를 꺼도 기존 건물 겹침 검사는 계속 작동한다.
- 시설은 서로 다른 종류도 함께 묶어 표시한다. 서울 전체에서는 숫자 묶음, 확대하면 시설별 아이콘으로 바뀐다. 아파트 제보 구역은 기본 표시에서 제외하지만 시설 토글·개별 검색·근거 팝업으로 볼 수 있다. 등록 좌표·개수·원문·현장 미확인 표시는 보존했다.
- 서울 OSM 참고 계산은 온라인 API를 이용한다. 월곡 안의 상세 계산·건물 검사·휴식·기존 GPS 기능은 기존 자료로 유지한다. **비교 시연**을 선택하면 기존 월곡 시연 위치와 단축 장소를 불러온다. 파일 실행에는 새 광역 그래프를 넣지 않는다.

## 계산과 한계

`POST /api/routes/city-walk`와 `GET /api/city/coverage`를 Node와 Vercel 함수에서 직접 처리한다. 기존 월곡 `/api/routes/walk`와 별도이며 ODsay 키·자료 서버·운영 DB 없이 실행된다. A*는 실제 인접 선분만 사용하며 계단 회피와 등록 경사 상한을 적용한다. 숫자 경사 상한에는 경사 미등록 구간을 허용하지 않는다. 경사 회피·휴식의 근거가 부족한 경우 조건을 자동으로 완화하지 않는다. 가장 짧은 거리 요청은 거리를 기준으로 계산한다.

출발·도착은 80m 안의 등록 노드에 대응시키며 핀과 해당 노드 사이의 연결은 미검증이다. 결과에는 그 간격을 별도로 표시한다. 경로 본문과 이 연결을 검증된 GPS 동선으로 제공하지 않는다. **서울 전역 GPS 경로 안내, 휴식 접속/운영시간/간격 검증, 휠체어 통행 가능 판정은 완성되지 않았다.**

교량·터널·실내·층위와 차단물 접속이 보류돼 있어 한강 횡단과 일부 같은 구/구 간 이동도 ‘연결 경로 없음’일 수 있다. 도로 중심선의 등록 경로는 보도 편·턱·출입문·현재 통행 권한을 입증하지 않는다. 기존 문서/빌드의 `citywide_routing:false`는 검증된 전역 보도망 미완료 상태로 유지하며 새 `city_walk.reference_routing:true`와 구분한다.

계산은 인스턴스당 최대 2개, 탐색 시간 8초·방문 노드 600,000개로 제한한다. 취소·과부하·시간 초과·결측·자료 손상은 명시적 오류다. 실패를 직선 경로나 조건 충족으로 대체하지 않는다. 키·실제 이용자 위치 로그를 저장하지 않으며 계산 요청에는 선택 좌표가 이 앱의 서버로 전달된다. 외부 길찾기 제공업체는 호출하지 않는다.

그래프 gzip 약 29.8MB와 way 등록정보 약 1.5MB를 서버에서 필요할 때 읽는다. 화면에 그래프 전체를 전송하지 않는다. 별도 자산 해시를 `service-integrity.json.city_assets`로 묶으며 손상/누락 시 503이다. Vercel이 JS를 변환할 수 있어 런타임에는 JSON/gzip 바이트를 검사하고 코드 원문 해시는 빌드 전에 검사한다.

## 재현과 배포

전처리 도구는 별도 개발 환경에서 `shapely==2.1.2`, `numpy==2.5.4`를 사용했다. 서버 실행에는 추가 npm/Python 패키지가 필요 없다. 준비 스크립트는 기존 출력이 있으면 중단한다. 새 버전 디렉터리에서 원본을 대조하고 `verify-city-walk.py`, `verify-city-buildings.py`로 검사한 뒤 별도 manifest 등록 상태·자산 해시를 명시적으로 갱신한다. 검증 전 manifest는 `validation_required:true`라 서버가 거부한다.

```sh
node server.mjs
node donghaeng-nav/scripts/test-city-walk.mjs
node donghaeng-nav/scripts/test-city-map-ui.mjs
node donghaeng-nav/scripts/test-city-layers.cjs
python3 donghaeng-nav/scripts/build-html.py
python3 donghaeng-nav/scripts/verify-city-release.py
```

현재 운영 주소의 이전 버전 문제는 [운영 반영 기록](deployment-status-2026-11-13.md)에 남아 있다. 최신 feature 커밋 배포를 `donghaeng-gill.vercel.app`에 연결해야 새 화면/API가 보인다. Vercel 프로젝트·도메인 변경 도구/인증이 이 환경에 없어 운영 별칭 변경과 main 병합은 수행하지 않는다. 커밋·푸시 시 일반 Vercel 자동 배포는 허용하며 배포 생략 표시는 사용하지 않는다.

## 푸시 후 실제 운영 재확인

기능 커밋 `11e531462da32b87d9642d69b9aac826255c73f3`을 같은 feature 브랜치에 푸시해 원격 SHA 일치를 확인했다. 두 Vercel 상태는 모두 success다. 이후 운영 주소를 다시 요청했지만 메인 HTML SHA-256은 기존 `26e707b085ed401130c92e2a99b127b16890d38c14bd8df78e4b097516409ede`이고 최신 소스와 다르며 `/expansion.html`·`/api/city/coverage`는 404였다. 이 주소에서 서울 기능이 이미 보인다고 표시하지 않는다. [배포 상태·공개 요청 기록](city-walk-publish-2026-11-13.json).

사용자 복귀 후 남은 계정 설정은 해당 운영 도메인이 연결된 프로젝트에서 최신 feature 배포의 Source/Production 연결을 확인하는 것이다. 이 환경의 도구로는 프로젝트/도메인 설정을 변경할 수 없어 그 부분은 보류했다. ODsay 실제 키 설정/인증도 확인 전이며 키 값을 요구하지 않았다.

## 2026-11-14 운영 반영 완료

사용자의 배포 요청에 따라 검증된 feature 커밋 `7c884b2`를 main에 fast-forward했고, 기존 main 이력을 보존했다. 공통 실행/배포 경로와 추가된 서비스/API를 대조했으며 운영 주소의 최신 화면·자료 API·실제 서울 도보 계산·모바일·정상 OSM 배경 로딩을 확인했다. 위 11월 13일의 운영 연결 보류는 해결됐다. [배포·구조·실제 검사 결과](production-deployment-2026-11-14.md). ODsay 키 설정은 확인했으나 실제 제공업체 검색은 호출하지 않았다. 기존 교량/휴식/접근성/GPS·현장 미검증 한계는 유지한다.
