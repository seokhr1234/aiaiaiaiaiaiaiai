# Gemini 경로 후보 비교와 선택 이유

2026-11-04. 사용자가 승인한 ‘후보 생성 → Gemini 비교·선택 → 선택 이유 버튼’을 구현했다. 길 찾기 버튼 한 번으로 조건 해석, 후보 탐색, 필요한 경우 AI 비교까지 진행한다.

## 후보 생성

`route-candidates.js`는 동일한 사용자 조건을 유지하며 최대 10회 탐색하고 최대 5개 후보를 남긴다. 경사·미확인 구간이나 이미 사용한 도로에 2.8/8/16배 탐색 패널티를 주어 다른 연결을 찾는다. 탐색 패널티 점수는 후보마다 달라지므로 알고리즘 기본 선택에는 패널티 없는 공통 엔진 비용을 다시 사용하고, AI 비교에는 공통 수치 지표를 전달한다. 경사 미확인을 0%로 간주하지 않는다. 약 3초의 탐색 예산을 반복 사이에 확인하며 개별 동기 탐색 도중에는 중단하지 않는다.

도로 길이 기준 90% 초과 중복 후보와 거리·최대 참고 경사·3% 초과 길이·미확인 길이·평가 불가 길이·접속 길이에서 모두 불리한 후보를 정리한다. 후보 수는 실제 연결에 따라 0~5개다. 3%는 비교용 집계 기준이며 법적/보편적 안전 기준이 아니다.

휠체어·계단 회피·수치 경사 상한·휴식 요구를 완화하지 않는다. 출발/도착 접속과 경로 본체·휴식 접속의 건물 겹침도 검사한다. 원본 그래프는 변경하지 않는다. 기존 engine/endpoint의 변경은 선택적인 탐색 패널티 전달이며 전역 경사 계수는 이번 작업에서 바꾸지 않았다.

적격 후보가 없으면 기존 검토용 경로는 AI 후보와 분리한다. 경사 제한을 푼 육교 검토 대안을 거리가 짧다는 이유로 기본 추천 맨 앞에 넣던 처리를 제거했다. 검토용 결과는 실제 GPS 안내를 시작할 수 없으며 독립 위치 추적·재생은 구분해 제공한다.

## API와 파일 모드

새 `POST /api/select-route`를 Node와 Vercel 공통 핸들러에 연결했다. 전달 항목은 상태 문장, 이동 조건, R1~R5 익명 번호별 거리·시간·참고 경사·미확인/접속 길이·휴식 여부뿐이다. 좌표·출발/목적지명·도로/시설명·지도 도형을 자동 전송하지 않는다. 서버는 추가 필드·형식·조건 위반을 검사하고 임의 경로 번호나 누락/중복된 후보 평가를 거부한다. 원래 상태 해석 API는 그대로 유지한다.

파일 모드에서는 PortableAI가 같은 요청 계약으로 직접 Google에 연결한다. 키는 창 메모리에만 유지하고 키 변경 후 이전 응답을 버린다. 안내와 README의 실제 전송 항목도 갱신했다. 이번 검사는 모의 Gemini이며 사용자 키의 실제 생성 요청은 실행하지 않았다.

후보 하나는 AI 비교를 생략한다. 여러 후보의 비교 실패·잘못된 응답·14초 비교 제한은 알고리즘 결과로 구분해 표시한다. 사용자 입력/출발/목적지/키 변경은 요청을 취소하고 늦게 도착한 선택과 설명을 적용하지 않는다.

## 선택 이유

선택된 카드에 ‘이 길을 선택한 이유’ 버튼을 추가했다. Gemini가 선택 시 함께 반환한 최종 요약·장점·감수한 점·미확인 사항·후보별 평가를 보관해 표시한다. 모델의 내부 추론은 요청하거나 표시하지 않는다. 버튼을 여러 번 눌러도 새 API 요청을 하지 않는다.

계산된 후보 수치 표는 엔진의 실제 집계를 사용하고, Gemini의 설명은 HTML이 아닌 텍스트로 표시한다. 다른 후보를 직접 선택하면 AI의 원래 추천 번호와 해당 후보 평가를 구분한다. 입력 변경이나 GPS 재탐색으로 경로가 바뀌면 과거 설명을 무효화한다. 경로를 저장했다 다시 열면 기존 흐름대로 재계산하며 이전 AI 설명을 새 경로에 재사용하지 않는다.

## 검증

- [코어·API 검사](route-choice-core-results.json): 세 갈래 합성 도로에서 3개 후보·제약·그래프 보존, 후보 없음/하나·취소, 익명 계약·가짜 ID·경사/계단 위반 거부, 명시적 휠체어/수치 제한 보존, 파일 분기·키 변경 응답 폐기, API 오류·429·시간 초과.
- [실제 자료 검사](route-choice-real-results.json): 현재 도로망과 도로 위 기준점으로 월곡역→도서관 2개, 일반 경사 회피 월곡역→학교 4개, 휠체어·5% 조건 월곡역→학교 0개를 확인했다. 현장 통행·사용자의 정확한 출입구 검증은 아니다.
- [브라우저 검사](route-choice-ui-results.json): 모의 Gemini가 3개 중 R2 선택, 당시 설명·표·추가 요청 없음, 직접 선택의 사유 분리, 모바일, 잘못된 ID 대체, 입력 변경 중 늦은 응답 폐기, 비교 취소/제한의 로컬 결과 유지, 적격 후보 없음의 AI 미호출·실제 GPS 제한. 합성 도로를 사용했고 브라우저 오류는 0건이다.
- 기존 내비게이션 코어 24개, condition API 회귀, Vercel 핸들러 회귀를 확인했다. Vercel의 새 route rewrite·파싱된 본문도 로컬에서 검사했다.

## 빌드·제한

자료 해시는 유지하고, 코어/실제 자료/브라우저 검사를 근거로 engine·endpoint의 변경과 새 후보/계약 모듈을 `runtime-integrity.json`에 명시적으로 기록했다. 원본 GIS를 재처리하거나 검증 해시 검사를 삭제하지 않았다. 공통 빌더가 현재 단일 HTML 5개와 해시를 갱신한다.

실제 Gemini·사용자 키/할당량·물리 GPS·휴대폰 파일 앱·턱/폭/출입구/시설 운행은 미검증이다. 데이터가 없어 조건을 만족하는 경로를 계산할 수 없으면 AI도 적합한 길을 만들어내지 않는다. 현재 요청은 로컬 구현이며 커밋·푸시·외부 배포는 수행하지 않았다.

## 후속 게시 요청

사용자가 새 브랜치 커밋·푸시를 요청해 `feature/gemini-route-selection`에 게시한다. 앞의 로컬 구현·미게시 문장은 구현 완료 당시 기록이다. main 병합과 Production 승격은 포함하지 않는다. Git 연동의 기본 브랜치 Preview 배포는 허용한다.
