# Gemini 경로 후보 비교와 선택 이유

2026-11-04. 사용자가 승인한 ‘후보 생성 → Gemini 비교·선택 → 선택 이유 버튼’을 구현했다. 길 찾기 버튼 한 번으로 조건 해석, 후보 탐색, 필요한 경우 AI 비교까지 진행한다.

## 후보 생성

`route-candidates.js`는 동일한 사용자 조건을 유지하며 최대 24회 탐색하고 최대 5개 후보를 남긴다. 경사·미확인 구간이나 이미 사용한 도로에 2.8/8/16배 탐색 패널티를 주어 다른 연결을 찾는다. 탐색 패널티 점수는 후보마다 달라지므로 알고리즘 기본 선택에는 패널티 없는 공통 엔진 비용을 다시 사용하고, AI 비교에는 공통 수치 지표를 전달한다. 경사 미확인을 0%로 간주하지 않는다. 약 4초의 탐색 예산을 반복 사이에 확인하며 개별 동기 탐색 도중에는 중단하지 않는다.

도로 길이 기준 짧은 경로의 90% 초과가 겹치는 후보를 정리한다. 거리·최대 참고 경사·3% 초과 길이·미확인/평가 불가 길이·계단/거친 노면·접속 길이의 비열등 후보를 먼저 채우고, 남은 자리는 도로가 다른 대안으로 채운다. 모든 수치가 불리해도 조금 길다는 이유만으로 대안을 전부 버리지 않는다. 단, 다른 수치상 이점 없이 다른 후보 거리의 1.5배+100m를 초과하는 대안은 제외한다. 후보 수는 실제 연결에 따라 0~5개다. 3%는 비교용 집계 기준이며 법적/보편적 안전 기준이 아니다.

휠체어·계단 회피·수치 경사 상한·휴식 요구를 완화하지 않는다. 출발/도착 접속과 경로 본체·휴식 접속의 건물 겹침도 검사한다. 원본 그래프는 변경하지 않는다. endpoint는 선택적인 탐색 패널티 전달과 갈림길의 일부 선분 제외 탐색을 지원하며 전역 경사 계수는 이번 작업에서 바꾸지 않았다. 갈림길 선분 제외는 같은 출발/도착점을 먼저 투영한 뒤 양방향에 적용하므로 옆 도로로 몰래 출발점을 바꾸지 않는다. 원본 그래프에는 적용하지 않는다.

적격 후보가 없으면 기존 검토용 경로는 AI 후보와 분리한다. 경사 제한을 푼 육교 검토 대안을 거리가 짧다는 이유로 기본 추천 맨 앞에 넣던 처리를 제거했다. 검토용 결과는 실제 GPS 안내를 시작할 수 없으며 독립 위치 추적·재생은 구분해 제공한다.

## API와 파일 모드

새 `POST /api/select-route`를 Node와 Vercel 공통 핸들러에 연결했다. 전달 항목은 상태 문장, 이동 조건, R1~R5 익명 번호별 거리·시간·참고 경사·미확인/접속 길이·휴식 여부뿐이다. 좌표·출발/목적지명·도로/시설명·지도 도형을 자동 전송하지 않는다. 서버는 추가 필드·형식·조건 위반을 검사하고 임의 경로 번호나 누락/중복된 후보 평가를 거부한다. 원래 상태 해석 API는 그대로 유지한다.

파일 모드에서는 PortableAI가 같은 요청 계약으로 직접 Google에 연결한다. 키는 창 메모리에만 유지하고 키 변경 후 이전 응답을 버린다. 안내와 README의 실제 전송 항목도 갱신했다. 이번 검사는 모의 Gemini이며 사용자 키의 실제 생성 요청은 실행하지 않았다.

후보 하나는 AI 비교를 생략한다. 여러 후보의 비교 실패·잘못된 응답·14초 비교 제한은 알고리즘 결과로 구분해 표시한다. 사용자 입력/출발/목적지/키 변경은 요청을 취소하고 늦게 도착한 선택과 설명을 적용하지 않는다.

## 선택 이유

선택된 카드에 ‘이 길을 선택한 이유’ 버튼을 추가했다. Gemini가 선택 시 함께 반환한 최종 요약·장점·감수한 점·미확인 사항·후보별 평가를 보관해 표시한다. 모델의 내부 추론은 요청하거나 표시하지 않는다. 버튼을 여러 번 눌러도 새 API 요청을 하지 않는다.

계산된 후보 수치 표는 엔진의 실제 집계를 사용하고, Gemini의 설명은 HTML이 아닌 텍스트로 표시한다. 다른 후보를 직접 선택하면 AI의 원래 추천 번호와 해당 후보 평가를 구분한다. 입력 변경이나 GPS 재탐색으로 경로가 바뀌면 과거 설명을 무효화한다. 경로를 저장했다 다시 열면 기존 흐름대로 재계산하며 이전 AI 설명을 새 경로에 재사용하지 않는다.

## 검증

- [코어·API 검사](route-choice-core-results.json): 세 갈래 합성 도로에서 3개 후보·제약·그래프 보존, 후보 없음/하나·취소, 익명 계약·가짜 ID·경사/계단 위반 거부, 명시적 휠체어/수치 제한 보존, 파일 분기·키 변경 응답 폐기, API 오류·429·시간 초과.
- [실제 자료 검사](route-choice-real-results.json): 현재 도로망과 도로 위 기준점으로 월곡역→도서관 5개, 일반 경사 회피 월곡역→학교 5개, 휠체어·5% 조건 월곡역→학교 0개, 루나밸리 중앙 아래쪽 도로 기준점→학교의 다리 통증/오르막 회피 5개를 확인했다. 현장 통행·사용자의 정확한 출입구 검증은 아니다.
- [브라우저 검사](route-choice-ui-results.json): 모의 Gemini가 3개 중 R2 선택, 당시 설명·표·추가 요청 없음, 직접 선택의 사유 분리, 모바일, 잘못된 ID 대체, 입력 변경 중 늦은 응답 폐기, 비교 취소/제한의 로컬 결과 유지, 적격 후보 없음의 AI 미호출·실제 GPS 제한. 합성 도로를 사용했고 브라우저 오류는 0건이다.
- 기존 내비게이션 코어 24개, condition API 회귀, Vercel 핸들러 회귀를 확인했다. Vercel의 새 route rewrite·파싱된 본문도 로컬에서 검사했다.

## 빌드·제한

자료 해시는 유지하고, 코어/실제 자료/브라우저 검사를 근거로 engine·endpoint의 변경과 새 후보/계약 모듈을 `runtime-integrity.json`에 명시적으로 기록했다. 원본 GIS를 재처리하거나 검증 해시 검사를 삭제하지 않았다. 공통 빌더가 현재 단일 HTML 5개와 해시를 갱신한다.

실제 Gemini·사용자 키/할당량·물리 GPS·휴대폰 파일 앱·턱/폭/출입구/시설 운행은 미검증이다. 데이터가 없어 조건을 만족하는 경로를 계산할 수 없으면 AI도 적합한 길을 만들어내지 않는다. 최초 구현은 후속 요청으로 기능 브랜치의 `7da3bc0`에 게시했으며 Vercel 배포 2건의 성공을 확인했다. 아래 후보 축소 수정은 같은 기능 브랜치에 후속 게시한다.

## 후속 게시 요청

사용자가 새 브랜치 커밋·푸시를 요청해 `feature/gemini-route-selection`에 게시한다. 앞의 로컬 구현·미게시 문장은 구현 완료 당시 기록이다. main 병합과 Production 승격은 포함하지 않는다. Git 연동의 기본 브랜치 Preview 배포는 허용한다.

## 2026-11-04 — 후보가 하나로 줄어드는 문제 수정

사용자는 루나밸리 부근→서울사대부중, “다리가 아파서 오르막이 어렵다” 조건에서 후보가 하나라고 보고했다. 정확한 핀 좌표는 공유되지 않아 `[37.5989,127.042]` 부근의 도로 투영점을 기준으로 재현했다. 학교 앞 목적지는 기존 프로그램의 같은 도로 기준점을 사용했다. `7da3bc0`에서 10회 탐색해 서로 다른 경로 7개를 만들었지만 엄격한 Pareto 필터가 6개를 버려 1개만 남았다. 이 단일 후보 설명은 Gemini 응답이 아니라 알고리즘 문구였다.

수정 후 같은 기준점/문장에서 서로 다른 후보 5개가 남는다. 루나밸리 내 추가 도로 기준점 3곳에서도 5개씩 확인했다. 전체 경로 일괄 가중치 외에 거리별 구간 가중치와 갈림길 일부 선분 제외를 사용한다. 최대 24회/약 4초, 중간 후보 풀 8개, 최종 최대 5개로 제한한다. 각 후보는 같은 사용자 조건과 건물 겹침 검사를 통과해야 한다. 차단으로 연결이 끊겨도 경사·계단 조건을 완화하거나 검토용 대안을 AI 후보로 넣지 않는다.

단일 후보는 “AI 비교는 하지 않았어요”라고 명시한다. 선택 이유의 ‘후보 탐색 결과’에서 시도/중복/조건·연결 제외와 탐색 한도 종료 여부를 확인할 수 있다. 하나만 찾았다고 가능한 모든 길이 하나라고 단정하지 않는다.

코어 검사는 동일 경사·서로 다른 길이의 세 갈래가 모두 남는 회귀, 입력 그래프 보존·차단 방향, 유일한 적격 분기 차단 후 급경사/계단으로 대체하지 않음, 중간 취소·횟수/시간 제한을 포함한다. 실제 도로망 검사에 루나밸리 재현 사례를 추가했다. 브라우저는 진짜 단일 경로의 AI 미호출/정직한 설명과 실제 도로망의 루나밸리 다중 후보를 모의 Gemini로 비교하는 흐름을 검사한다. 정확한 사용자 핀·실제 Gemini 답변 품질·현장 통행은 미검증이다.
