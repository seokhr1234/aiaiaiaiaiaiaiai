## A01 — 휴식이 필요한 재탐색에서 필수 경유가 사라짐

관련: `dist/navigation-routing.js:22`, `dist/navigation-session.js:32`. [함수 재현](module-results.json), [안내 세션 재현](reroute-session-result.json).

실제 내장 도로망과 월곡역→도서관 앞 도로 기준점으로, 휴식이 포함된 초기 경로를 만든다. 위치가 유효한 안내 세션에서 대체 경로 계산 시 지역 휴식 후보 229개를 모두 이용 불가로 모의 처리한다. 현장 폐쇄를 주장하는 검사가 아니라 **대체 휴식 장소가 없는 실패 상황**을 만든 것이다.

결과는 `rerouteApplied:true`, `profile.rest:true`, `plan.rest:null`, `restFulfilled:false`다. 원문 메시지는 “휴식 조건은 충족되지 않았습니다”라고 나오는데도 대체 경로가 세션에 적용되고 새 위치를 기다린다. 최초 후보 선택은 이 경우를 제외하지만 재탐색 적용 지점은 위험 대안 여부만 확인한다.

재탐색에서도 원래 이동 조건·휴식 종류·간격·기하 연결을 검사해야 한다. 이미 휴식 완료한 경우는 별도로 허용하되, 이용 불가를 휴식 요구의 철회로 취급하면 안 된다. 후보가 없으면 `reroute-failed`로 남기고 사용자의 다음 선택을 안내하는 것이 적절하다. 실패 상태·정상 대체·이미 휴식 완료를 나눠 검사해야 한다.

## A02 — 초기 자료가 무겁고 필수 부팅 경로에 묶임

관련: `dist/data-loader.js:4`, `:9`, `:18`, `dist/index.html`, `donghaeng-nav/server.mjs`의 정적 응답 처리. [기본 브라우저 측정](browser-results.json), [느린 모바일 측정](slow-mobile-results.json).

9개 JSON/GeoJSON은 합계 **88,911,227 bytes**다. 서울 전역 배경 약 27.0MB, 시설 약 21.3MB, 정밀지도 약 15.9MB도 처음부터 순서대로 읽는다. 로더는 각 응답을 파싱 확인하고 script text에 보관하며 앱에서 다시 사용한다. 마지막 자료 전에는 길 찾기 버튼을 쓸 수 없다.

- 로컬 데스크톱 기본 측정: 약 **3.58초**, JS heap 약 **172MB**, 가장 긴 main-thread 작업 약 **1.31초**.
- 새 393×852 컨텍스트, 다운로드 512,000 bytes/s·지연 80ms·CPU 4배 감속: 약 **184.7초**, 가장 긴 작업 약 **3.63초**, JS heap 약 **177MB**.

이는 **로컬 Node 서버·비압축 응답·브라우저 감속 모의 측정**이다. 실제 휴대폰·Vercel gzip/Brotli·실제 통신망을 측정한 값으로 일반화하지 않는다. 컨텍스트의 요청 가로채기로 HTTP 캐시도 비활성화돼 있어 일반 재방문 속도와도 구분한다. heap은 브라우저 전체 메모리가 아니다.

경로 계산에 필요한 지역 도로망을 먼저 준비하고 서울 전역 시설·배경·검토 레이어는 지연 로딩/지역 분할을 검토할 만하다. Node 서버 압축과 조건부 캐시도 도움이 된다. 단, 필수 기하 검증을 생략한 상태로 경로를 먼저 추천해서는 안 된다. 필요한 검증 자료를 더 작게 나누는 방식이 필요하다.

## A03 — 기본 해석의 내리막·부정·문맥 처리

관련: `dist/engine.js:5`. [해석 재현](module-results.json), [실제 화면 경로](routes-results.json).

실제 환경처럼 Gemini 키가 없을 때 다음을 확인했다.

| 입력 | 실제 결과 |
| --- | --- |
| `내리막을 피하고 싶어요.` | `avoidSlope:false`, `recognized:false` |
| `내리막이 힘들어서 경사가 없는 길로 가고 싶어요.` | `avoidSlope:false`, `recognized:false` |
| `오르막을 피하고 싶어요.` | `avoidSlope:true` |
| `계단이 힘들지 않아요.` | `avoidSteps:true` |
| `쉬운 길로 가고 싶어요.` | `rest:true` |
| `휠체어를 쓰지 않습니다.` | `wheelchair:true` |

내리막 요청 누락은 실제 화면의 최종 profile에서도 확인했다. 나머지는 해석 함수 재현이다. 화면은 기기 내 해석임을 밝히고 있어 AI 성공으로 위장하는 문제는 없었다. 실제 Gemini도 같은 오해를 한다는 뜻은 아니다.

회피 대상에 내리막을 포함하고 `힘들지 않다/쓰지 않다` 같은 부정, `쉬운`과 `쉬다`의 차이를 다루는 편이 좋다. 입력 아래에 **이번 경로에 적용한 조건**을 제출 전후 명확히 보여 주면 누락 발견에 도움이 된다. 기존 지침대로 별도 AI 버튼·조건 체크박스를 되살릴 필요는 없다.

## A04 — 쉼터 운영시간 검사가 도착 시각을 고려하지 않음

관련: `dist/engine.js:33`의 `restStatus(place, p.atTime || new Date())`. [합성 경로 재현](module-results.json).

3개 노드의 직선 보행 경로와 09~18시 운영 쉼터를 사용했다. 화요일 17:59 출발, 쉼터까지 111.2m, 보행속도 65m/분이면 도착은 약 **18:00:43**이다. 그런데 출발 시각에는 열려 있다는 이유로 쉼터가 선택된다. 같은 자료를 도착 예상 시각으로 조회하면 자동 경유 제외가 나온다.

이는 합성 시설 검사이며 특정 실제 시설이 해당 시각에 닫았다는 주장이 아니다. 현장 상태가 미확인이더라도 **이미 등록된 종료 시각과 예상 도착이 충돌**하는 것은 미리 걸러낼 수 있다. 경유까지 거리와 여유 시간을 반영해 운영 여부를 확인하고 도착 전 마감 가능성을 알려야 한다.

## A05 — 작은 화면에서 팝업 닫기를 누를 수 없음

관련: `dist/facilities.js:33`. [새 모바일 컨텍스트 측정](accessibility-results.json), [화면](small-screen-popup-fresh.png), [팝업과 하단창 측정](browser-results.json).

320×568에서 성북문화예술교육센터를 열면 팝업은 폭 **347px**, 범위 x=10~357이다. 닫기 버튼은 **x=333~357**로 320px 화면 밖에 있으며 중심점 hit test도 실패한다. 일부 내용은 하단 접힌 창과 겹친다. 문서 전체의 가로 스크롤은 늘지 않아 기존 `scrollWidth <= innerWidth` 검사만으로 잡히지 않는다.

팝업 `maxWidth:300`에 Leaflet 외부 여백이 더해지는 점과 세로 가용 영역을 함께 계산해야 한다. 작은 화면에서 전체 팝업 경계·닫기 버튼 hit test·하단창 충돌을 검사하는 것이 좋다. 보호 경고 내용은 유지해야 한다.

## A06 — 저장 자료의 구조가 바뀌면 화면이 복구되지 않음

관련: `dist/app.js:3`, `:163`, `:187`. [브라우저 재현](browser-results.json).

새 브라우저 컨텍스트의 localStorage에 아래 값을 넣고 저장/제보 화면을 열었다. JSON 문법 오류는 잡지만 **JSON 결과의 배열·항목 형태는 검사하지 않는다.** 정상 저장 데이터가 자동으로 이렇게 변했다는 주장은 아니다.

| 키/값 | 결과 |
| --- | --- |
| routes `{}` | `items.forEach is not a function` |
| routes `[null]` | `Cannot read properties of null (reading 'destination')` |
| routes `[{"id":1,"name":"old route"}]` | `Cannot read properties of undefined (reading 'name')` |
| reports `{}` | `items.slice is not a function` |

저장/제보 내용이 비거나 렌더링이 중단되고 문제 항목을 화면에서 지우기 어렵다. 이전 버전·손상 자료·다른 형식의 사이트 데이터에 대비해 배열과 항목을 검증하고, 정상 항목은 살리며, 복구/초기화 선택지를 제공하는 것이 좋다. 저장소 접근 자체가 거부되는 문제와는 다른 경우다.

## A07 — 기본 빠른 목적지와 진입 연결의 불일치

관련: `dist/app.js:222`의 목적지 구성, 공통 건물 겹침 검토. [7개 경로 흐름](routes-results.json), [기본 도서관 화면](default-library-route.png).

기본 월곡역 출발에서 “가장 짧은 길”을 입력했다.

- 학교: 일반 후보 **5개**, GPS 시작 가능.
- 삼각형 쉼터: 일반 후보 **3개**, GPS 시작 가능.
- 꿈그림도서관: 추천 후보 없음, 검토용 **1개**, GPS 시작 불가. 도착 연결 10.5m 중 약 7.7m가 건물 도형과 겹친다.
- 정류장 의자: 검토용 **1개**, GPS 시작 불가. 도착 연결 4.7m 중 약 2.0m가 건물 도형과 겹친다.

겹침 검사·검토용 구분 자체는 정상이다. **이를 끄는 수정은 권장하지 않는다.** 자주 쓰는 기본 목적지를 선택해도 정상 경로가 안 나오는 원인과 다음 동작이 사용자에게 더 빨리 드러나야 한다. 시설 대표점과 실제 출입구/보행접속점을 구분하고, 출입구 근거가 없으면 지도에서 진입 위치를 정하는 공통 흐름을 보완하는 편이 좋다. 지명별 하드코딩이나 임의 좌표의 현장 검증 승격은 피한다.

## A08 — 시설 일반 안내의 글자 대비와 크기

관련: `dist/style.css:12`. [계산 스타일·대비 결과](accessibility-results.json).

흰 팝업 배경에서 일반 `dt`는 11px·`rgb(126,140,119)`로 약 **3.56:1**, 일반 안내 `p`는 10px·`rgb(135,146,126)`로 약 **3.26:1**이다. 일반 본문에 흔히 쓰는 4.5:1 대비 목표보다 낮고, 현장 상태·이용 조건 안내가 작다. 새 주황 경고의 진한 글자는 이 문제에 포함하지 않는다.

출처·운영·현장 미확인처럼 의사결정에 필요한 일반 글자는 크기와 대비를 함께 높이고 200% 확대도 확인할 만하다. 이 검사는 계산 스타일 측정이며 실제 저시력 사용자나 화면낭독기 검사를 대체하지 않는다.

## A09 — 경로 선택 후 키보드 초점이 사라짐

관련: `dist/app.js:142`의 선택 버튼 재생성. [키보드 검사](accessibility-results.json).

학교 경로의 두 번째 후보 선택 버튼에 키보드 초점을 두고 Enter를 누르면 선택은 2번으로 바뀌지만 `document.activeElement`는 BODY가 된다. 다음 Tab은 선택한 후보의 다음 행동으로 이어지지 않고 첫 후보 버튼으로 돌아왔다. 이전 검사 시도는 후보 버튼 대신 다른 액션을 집어 초점 증거로 사용하지 않았고, 최종 재현은 `aria-pressed`가 있는 후보 선택 버튼만 대상으로 했다.

재렌더 후 동일 후보 버튼에 초점을 복원하거나 요소를 유지하는 방식이 좋다. 후보 선택은 성공하므로 P3 조작 개선으로 분류했다.

## 정상 동작도 확인한 범위

- 학교·삼각형 쉼터의 일반 경로는 생성됐다. 휠체어 조건을 만족하지 못한 경우에는 일반 추천/GPS 시작을 차단했다.
- 키 미설정은 기기 내 해석으로 명시했다. 정상 저장 후 모바일에서 같은 조건으로 다시 찾기는 동작했다.
- [모의 AI 검사](mock-ai-results.json)에서 R2 선택과 화면 선택 ID가 일치하고 선택 이유가 열렸다. 조건 수정 후 늦게 도착한 모의 응답은 기존 경로를 되살리지 않았다.
- 모의 AI 요청은 상태 문장과 익명 후보 수치였고 좌표/목적지 이름의 별도 필드는 없었다. 이것은 요청 구조 검사이며 실제 Google 응답 품질 검증이 아니다.
- 원래 건물 겹침 보호·공식자료 불일치 표시·기존 자료의 미검증 구분을 유지했다.

## 재현

저장소 최상위에서 서버를 실행한 뒤 별도 터미널에서 실행한다. Playwright와 `/usr/bin/chromium`이 필요하며 로컬 HTTP/브라우저 실행 권한은 환경에 맞게 사용한다.

```sh
node server.mjs
node donghaeng-nav/docs/audit-2026-11-10/browser-audit.cjs
node donghaeng-nav/docs/audit-2026-11-10/browser-audit.cjs --slow
node donghaeng-nav/docs/audit-2026-11-10/routes-audit.cjs
node donghaeng-nav/docs/audit-2026-11-10/module-audit.cjs
node donghaeng-nav/docs/audit-2026-11-10/reroute-session-proof.cjs
node donghaeng-nav/docs/audit-2026-11-10/accessibility-audit.cjs
node donghaeng-nav/docs/audit-2026-11-10/mock-ai-audit.cjs
```

결과의 시간·메모리·좌표는 해당 실행의 관측값이다. 이 코드는 감사용 실험이며 전체 검사가 통과해야 하는 제품 회귀 검사로 등록한 것이 아니다. 화면 저장소의 합성 값은 새 컨텍스트에만 넣었다.

## 다음 작업과 중단 지점

먼저 A01의 재탐색 계약을 고치고 A03·A05를 회귀 검사로 묶는 것을 권한다. 그다음 초기 자료 분할과 목적지 접속 자료를 다루는 편이 좋다. 이번에는 발견·재현·우선순위 정리까지 했으며 제품 수정을 진행하지 않았다.
