## 지금 실행할 수 있는 것

저장소 최상위에서 `node server.mjs`로 실행한다. 기본 화면은 기존 동행길이고, **자료·서비스 안내 → 지역별 자료·경로 보기** 또는 `http://127.0.0.1:4173/expansion.html`에서 새 조회 화면을 연다. 브라우저가 파일로 실행되는 단일 HTML에는 온라인 확장 링크를 숨긴다.

새 화면은 전체 도로망·정밀지도·시설 JSON을 브라우저로 내려받지 않고 현재 지도 영역만 요청한다. 등록 시설 이름·주소를 검색하거나 지도에서 출발·도착을 정할 수 있다. 현재 서버 보행 계산 범위는 기존 월곡역 주변이다. 범위 밖은 명시적으로 거부하며 최근접 도로로 몰래 이동시키지 않는다.

대중교통 화면은 좌표 전송 안내와 함께 **참고 후보**만 제공한다. 실제 안내 시작 버튼을 만들지 않았다. 키가 설정되어도 응답을 받기 전에는 연결 성공으로 표시하지 않는다. 키가 없거나 API가 실패하면 이유를 알리고 조건을 완화한 가짜 경로를 만들지 않는다.

기존 메인 화면·GPS·오프라인 HTML은 유지한다. 기존 메인 화면이 새 화면의 준비 시간으로 빨라졌다고 주장하지 않는다. [연결 방법](expansion-service.md)을 참고한다.

- 원본 PBF·응답 바이트와 무손실 gzip 파생본은 새 조사 폴더에 로컬 보관하고 대용량 원본은 Git에서 제외한다. 계획·수집 메타데이터·해시·추출 코드·검증 결과는 남긴다. 이전 round3/round4 및 런타임 자료 9개는 보존한다. [새 조사 기록](../../research/accessibility/round5-2026-11-11/README.md), [카탈로그](seoul-source-catalog.json).

PostGIS 3.5.7의 격리된 로컬 시험 DB에 정밀 16,169 + 시설 17,485 + 횡단 참고점 1,260 = **34,914건**을 이관했다. 모든 인덱스용 기하가 유효하며 원본 JSON 기하를 별도 열에 보존한다. 지정 영역의 시설 61건 조회도 확인했다. 현장 검증으로 승격한 행은 0건이다. [DB 결과](expansion-postgis-results.json).

## 다음 재개 순서

1. 현재 변경·무결성 기록·검사 결과와 실제 파일을 대조한다. 기존 연구와 새 로컬 원본의 존재 여부도 확인한다.
2. 사용자가 Vercel에 `ODSAY_API_KEY`를 등록한 뒤 새 배포에서 `/api/transit/status`와 소량 실제 참고 검색을 확인한다. 서버 플랫폼/호출 제한·OSM 병용·결과 가공/보관 조건도 확인한다. 채팅·Git에 키를 넣지 않는다.
3. 운영할 보행 백엔드·DB를 준비하고 `DONGHAENG_BACKEND_URL`과 인증을 연결한다. 이 작업에서 운영 호스팅 가입·결제·배포를 실행하지 않았다.
4. 새 OSM 관계 외부 참조·보행 제한·건물/출입구/층위와 그래프 재구성을 검토한다. 바뀐 그래프에는 이전 지형 근거를 해시 검증 없이 재사용하지 않는다.
5. NGII 전역 원본 접근 재확인과 시범 보도/횡단/출입구 조사를 진행한다. 확보·확인한 범위만 확대한다.
6. 운행 시간표·승강기/저상 차량·역내 연결을 실제 여정 검증 모듈에 연결하고 현장·실기기 검사로 진행한다. 전체 일정의 휴식 간격과 승하차 자동 감지는 후속이다.
