## 지금 실행할 수 있는 것

저장소 최상위에서 `node server.mjs`로 실행한다. 기본 화면은 기존 동행길이고, **자료·서비스 안내 → 지역별 자료·경로 보기** 또는 `http://127.0.0.1:4173/expansion.html`에서 새 조회 화면을 연다. 브라우저가 파일로 실행되는 단일 HTML에는 온라인 확장 링크를 숨긴다.

새 화면은 전체 도로망·정밀지도·시설 JSON을 브라우저로 내려받지 않고 현재 지도 영역만 요청한다. 등록 시설 이름·주소를 검색하거나 지도에서 출발·도착을 정할 수 있다. 현재 서버 보행 계산 범위는 기존 월곡역 주변이다. 범위 밖은 명시적으로 거부하며 최근접 도로로 몰래 이동시키지 않는다.

대중교통 화면은 좌표 전송 안내와 함께 **참고 후보**만 제공한다. 실제 안내 시작 버튼을 만들지 않았다. 키가 설정되어도 응답을 받기 전에는 연결 성공으로 표시하지 않는다. 키가 없거나 API가 실패하면 이유를 알리고 조건을 완화한 가짜 경로를 만들지 않는다.

기존 메인 화면·GPS·오프라인 HTML은 유지한다. 기존 메인 화면이 새 화면의 준비 시간으로 빨라졌다고 주장하지 않는다. [연결 방법](expansion-service.md)을 참고한다.

기반 구현 **`9282ea656c3879ae097aa0622973137053ea2873`**을 같은 feature 브랜치에 푸시했고 원격 SHA가 일치한다. 연구/측정 체크포인트 **`5d28dcc8875e08770fd9dba8b0780557b5f11f29`**도 푸시해 원격 SHA와 두 Vercel success 상태를 확인했다. 이어서 이미 위험 검토 후보를 금지한 고정 서버 그래프의 객체를 재사용해 건물 필터 캐시가 요청 간 유지되도록 했다. 실제 도로망 12쌍·4조건의 이전 코드 대조, 기존 후보·서버·모바일·메인/새 단일 HTML 검사를 통과했다. 같은 100쌍 결과는 69/31/0으로 그대로이고 p50 2,173ms·p95 5,230ms, 동시 처리 p95 6,571ms였다. p95 개선이나 전역 목표 달성으로 표시하지 않는다. ## 다음 재개 순서

2. 사용자가 Vercel에 `ODSAY_API_KEY`를 등록한 뒤 새 배포에서 `/api/transit/status`와 소량 실제 참고 검색을 확인한다. 서버 플랫폼/호출 제한·OSM 병용·결과 가공/보관 조건도 확인한다. 채팅·Git에 키를 넣지 않는다.
3. 확인한 운영 주소 `donghaeng-gill.vercel.app`에 최신 feature 커밋을 연결한 후 확장 화면·API를 다시 검사한다. 실제 운영 배포/도메인 설정은 Vercel에서 확인해야 한다. 운영할 보행 백엔드·DB를 준비해 `DONGHAENG_BACKEND_URL`과 인증을 연결한다. DB 조회는 자료 서버의 `DONGHAENG_DATABASE_URL`을 사용한다. 이 작업에서 운영 호스팅 가입·결제·배포를 실행하지 않았다.
4. 새 OSM의 628개 제한 구조 신호와 검토 그래프의 4,374개 성분/경계 분리 사유, 보도/건물/층위·차단물 정책을 검토한다. 검증한 시범 부분부터 버전 고정 이관하며 남은 AH1 참조 977개는 부재로 보존한다. 바뀐 그래프에 이전 지형 근거를 해시 검증 없이 재사용하지 않는다.
