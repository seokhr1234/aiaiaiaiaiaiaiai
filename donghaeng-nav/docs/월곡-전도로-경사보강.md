# 월곡역 전 도로 경사 보강과 루나밸리 시연 · 2026-10-31

이 문서가 이전 ‘휠체어 경사 우회 수정’의 데이터 범위·대안 동작 설명보다 우선합니다. 원본 경사값·독립 이동 추천과 **위험 검토용 참고값**을 구분합니다.

## 범위와 결과

내장 도로망 **21,553개 고유 구간 전부**에 처리 상태를 붙였습니다. 기존 6개 타일에 공개 Tilezen 고도 타일 14개를 추가해 도로망 전체와 표본 여유를 포함하는 총 20개 타일로 보강했습니다.

| 분류 | 구간 수 | 의미 |
| --- | ---: | --- |
| OSM 수치 등록 | 2 | 등록 경사, 현장 실측 여부 미검증 |
| 기존 유효 Tilezen 참고 추정 | 14,551 | 기존 원시 추정값 보존 |
| 자료 차이 범위 | 2,461 | 서로 다른 자료·창의 참고값 묶음, 정확도 오차 구간이 아님 |
| 보완 주변 지형 추정 | 3,872 | 도로 방향 중심 ±30m, 60m 주변 지형의 참고 추정 |
| 구조물·계단 등 별도 확인 | 667 | 지형 고도를 실제 노면 높이로 대입하지 않음 |
| 고도 결측 | **0** | 지형을 적용할 수 있는 구간의 고도값 누락 없음 |

**모든 보도 경사를 실측했다는 뜻이 아닙니다.** 구조물 667구간과 임의 출발·도착점에서 도로망까지의 연결은 노면 경사·출입 동선 미확인입니다. 구조물에 0%나 임의 숫자를 채우지 않습니다.

## 계산 방법과 출처

- `scripts/terrain-screening.py`에서 실제 실행 그래프의 모든 고유 edge를 추출하고 분류합니다. 결과는 `dist/terrain-data.json`의 `screening`에 있으며, 기존 `edges`·`nodeElevations`는 변경하지 않습니다.
- 짧은 도로 때문에 원래 방식으로 30m 지지거리가 확보되지 않는 경우 주변 지형의 **60m 방향별** 높이를 7개 표본으로 읽습니다. 선형회귀의 높이 변화/수평거리와 양 끝 높이 차/60m를 비교해 참고 범위로 저장합니다. 이는 보도 노면의 짧은 구간 실측 경사가 아니고, 골목 연장선이 건물·다른 지형을 지날 수 있습니다. 출력 픽셀 간격은 원천 DEM 정확도·실효 해상도가 아닙니다.
- 자료가 다른 구간은 원래 값을 삭제하거나 한쪽을 정답으로 고르지 않습니다. 자료별 절대 경사 참고값의 최소·최대 묶음을 `source_range`로 분리합니다. 서로 다른 수직 기준의 표고를 합쳐 경사를 새로 만들지 않습니다. 상단값을 위험 회피에 보수적으로 사용하며 실제 노면 경사의 상한이라고 주장하지 않습니다.
- 교량·고가·터널·지하·층위 불명·계단 등은 별도 확인 대상으로 남깁니다. 기존 `slopeOf()`에 보완·충돌값을 확정 경사로 주입하지 않습니다. `screeningGrade()`는 구분된 위험 검토에만 사용합니다. 서울시·Copernicus의 노면 경사 승격은 여전히 0개입니다.
- [Tilezen 공개 고도](https://registry.opendata.aws/terrain-tiles/)와 [출처·이용조건](https://github.com/tilezen/joerd/blob/master/docs/attribution.md). 추가 다운로드 URL과 SHA-256은 `data/terrain/screening-tiles.json`에 기록했습니다. 원래 `tile-audit.json`, 조사 원본, 라이선스는 보존했습니다.

## 휠체어 경로와 위험 대안

1. 등록 계단·휠체어 불가 구간을 제외하고, 참고값/범위 상단 5% 초과 회피를 먼저 적용합니다. 더 엄격한 요청은 유지합니다. 5%는 제품의 추천 회피 정책값이며 통행 안전 기준이 아닙니다.
2. 조건을 만족하는 경로가 있으면 우회 후보로 표시합니다. 미확인을 평지로 취급하지 않습니다.
3. UI에서 조건을 만족하는 경로가 없을 때는 탐색 결과를 빈 화면으로 끝내지 않고 **이동 지원 필요·위험 대안**을 별도로 표시합니다. 기본 엔진 호출은 기존처럼 조건 불충족 시 실패하며, 실제 화면에서만 `graph.meta.allowAssistancePreview`를 명시적으로 사용합니다.
4. 위험 대안은 먼저 경로 전체의 가장 높은 참고 경사 상단값을 최소화하는 탐색을 합니다. 가능한 상단값 집합에서 이분 탐색과 Dijkstra로 연결 가능성을 확인하고, 가장 낮은 연결 상단 안에서 경사 노출·불확실성·거리 비용을 비교합니다. 짧은 급경사를 위해 더 완만한 긴 우회를 버리지 않도록 했습니다. 휴식 경유에도 동일한 상단을 적용합니다.
5. 위험 대안은 독립적인 휠체어 이동 추천이 아닙니다. 빨간 위험 선, 주황 자료 차이, 보라 구조물·결측을 지도에 표시합니다. 급경사 회피에 성공했다고 표시하거나 ‘안전한 경로’라고 부르지 않습니다. 계단·휠체어 명시 불가 구간은 위험 대안에서도 제외합니다.

## 실제 루나밸리→서울사대부중 시연

- ‘루나밸리 출발’은 내장 OSM 단지 서측 경계점 `[37.5995513,127.0412035]`입니다. 확인된 출입구라고 표시하지 않으며 GPS/핀으로 실제 위치를 바꿀 수 있습니다.
- ‘서울사대부중’ 빠른 목적지는 **학교 건물 대표점**입니다. 이전 정류장 시연과 다릅니다. 도착 연결 약 98m는 출입구 동선 미검증입니다.
- 실제 Gemini로 휠체어·경사/계단 회피 문장을 해석해 경로를 계산했습니다. 기준점에서 약 **705m**, 도로 18구간, 고도 결측 **0m**, 등록 계단 0구간입니다. 도로 중 구조물 약 56m와 도로망 밖 출발/도착 연결이 미검증입니다.
- 현재 자료 범위 상단이 약 **6.19%**인 구간이 남아 5% 회피를 충족하는 독립 이동 추천은 만들지 못했습니다. 따라서 이 결과는 명시적인 **위험 대안**입니다. 고도 자료 누락으로 경로 계산이 중단되는 문제를 고쳤지만, 현장 안전을 입증하지 않았습니다.
- 루나밸리 내부/주변 세 출발점과 월곡역에서 실제 학교 대표점까지 각각 검사했습니다. 결과는 `terrain-screening-results.json`, 실제 제공자는 `luna-live-results.json`입니다.

## 실행·검증

`동행길-실행.command`를 열고 실행 주소에 `?demo=luna-wheelchair`를 붙이면 상태 입력부터 자동 시연합니다. 파일 단독 실행에서도 지도·경사 근거·경로 계산이 되며 AI 서버 미연결/기기 내 해석 사용을 표시합니다. `동행길-최종.html`과 `동행길-시연.html`은 동일한 최신 결과입니다.

- `node donghaeng-nav/scripts/test-terrain-screening.cjs`: 모든 구간 분류, 고도 결측 0개, 구조물에 임의 수치 없음, 자료 범위와 원래 경사 구분, 짧은 급경사 대신 낮은 최대 경사의 긴 대안, 루나밸리 여러 출발점 검사.
- `node donghaeng-nav/scripts/test-terrain-screening-ui.cjs`: 루나밸리·학교 선택, 단일 AI 제출, 위험 대안 문구, 모든 구간 근거 목록, 실제 지도 위험 선, 시설 토글 독립, 모바일 검사.
- `test-terrain-review.cjs`: 지형 원본 값 보존·GIS 비교 검증.
- `test-auto-plan-ui.cjs`, `test-final-ui.cjs`: AI 취소/재시도·저장·기기 내 해석·시설 토글·순서·모바일 기존 동작 검사.
