# 남쪽 경로 선택 원인과 공통 엔진 수정 · 2026-10-31

## 확인한 원인

경로를 북쪽으로 강제하는 지점·좌표·도로명 규칙은 추가하지 않았습니다. 실제로 문제였던 것은 **미확인 구조물의 위험이 최대 경사 비교에서 빠진 것**입니다.

이전 `assistanceAlternative()`는 숫자로 계산되는 경사값의 상단을 먼저 최소화했습니다. 교량·층위 등 노면 높이를 지형 고도로 대체할 수 없어 `null`로 둔 구간은 그 최대값 집합에 들어가지 않았습니다. 도로 비용에 결측 가중치가 있더라도, 앞 단계에서 최대 경사를 먼저 고정한 뒤에는 다른 경로를 선택할 수 없었습니다. 결과적으로 남쪽의 구조물 약 56m가 숫자로 확인되는 경사보다 유리하게 취급됐습니다. 자료가 모두 있다고 주장하거나 북쪽 지점을 강제하는 방식으로 고칠 문제가 아니었습니다.

## 바꾼 계산

- 휠체어 Dijkstra의 경로 점수를 `(지형 적용 불가 구조물·고도 결측 통과 거리, 이동 부담 비용)`으로 비교합니다. 숫자 없는 노면이 평지와 같은 순위를 얻지 않습니다. 이 우선순위는 모든 장소에 동일합니다.
- 위험 대안을 만드는 경우, 먼저 전체 연결망에서 위 미확인 통과량의 최소값을 구합니다. 그 최소값을 유지하는 경로들 사이에서 가장 높은 참고 경사를 낮추고, 최종적으로 이동 부담·거리를 비교합니다.
- 벤치·쉼터 경유도 원래 경로보다 미확인 통과량이 늘어나면 제외합니다. 휴식 선호가 앞선 회피 기준을 깨지 않게 했습니다.
- 일반 사용자의 거리 우선 경로는 기존 거리 계산을 유지합니다.
- 북쪽 좌표, 월곡역 경유, 도로명/OSM ID 예외를 경로 선택에 넣지 않았습니다. 기존 시연의 출발·목적지 좌표는 그대로입니다.

## 같은 입력의 비교

| 항목 | 이전 | 수정 후 |
| --- | ---: | ---: |
| 연결 구간 포함 거리 | 약 705m | 약 3,008m |
| 지형 적용 불가·결측 노면 통과량 | 약 56m | 0m |
| 참고 자료 상단 | 6.19% | 6.41% |
| 출발 후 진행 | 남쪽 | 북쪽, 월곡역·월곡로 쪽 |

수정 후 화랑로·월곡로16길·월곡로를 지나 북쪽·서쪽으로 크게 우회합니다. 사용자께서 말한 북쪽 방향은 반영된 결과로 나타나지만, 지정 경유지로 강제하지 않았습니다. 상세 비교 좌표·입력 해시는 `routing-uncertainty-diagnosis.json`에 있습니다.

**약 3km라는 긴 우회도 현재 자료의 한계입니다.** 구조물의 실제 노면 경사를 모르는 상태에서 그 구간을 먼저 피하고 참고 경사를 낮추면 이런 결과가 나옵니다. 이 경로가 현장의 최적 길 또는 안전한 휠체어 통행 경로라고 검증된 것은 아닙니다. 최대 참고값이 5% 정책을 넘으므로 여전히 ‘이동 지원 필요·위험 대안’입니다. 구조물·결측 통과 0m도 모든 보도를 실측했다는 뜻이 아닙니다. 건물 대표점까지의 마지막 연결 약 98m는 별도 미검증입니다.

## 검증

- `test-routing-uncertainty.cjs`: 짧은 미확인 교량길과 긴 참고 경사 경로를 가진 가상 도로망에서 긴 경로를 선택합니다. 좌표를 90도 회전해도 같은 노드 경로를 선택하므로 북쪽 편향이 아닙니다. 일반 거리 우선은 짧은 길을 유지합니다.
- 실제 루나밸리→학교 입력은 경유지 없이 북쪽으로 이동하고 구조물 통과 0m를 확인했습니다.
- 기존 전 도로 경사 분류·지형 원본 보존·AI 상태 해석·벤치·쉼터·순서·시설 토글·모바일 검증을 수행했습니다. 최신 결과 JSON과 Chrome 화면을 함께 갱신했습니다.
