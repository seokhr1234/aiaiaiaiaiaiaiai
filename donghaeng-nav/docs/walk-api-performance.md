# 서버 보행 계산 기준선 — 2026-11-11 KST

서울 전역 목표를 통과했다고 표시하지 않는다. 현재 월곡 도로망에서 공개 도로 노드의 고정 100쌍으로 측정한 **로컬 기술 시연 성능**이다. 원본 해시·표본 ID·직선 거리·조건별 상태·개별 시간을 [측정 원문](walk-api-local-performance.json)에 남겼다. 실제 사용자 GPS·위치 기록·외부 API 호출은 없다.

`benchmark-walk-api.mjs`는 seed 20261111로 같은 현재 그래프의 주요 연결 성분 안에서 150~1,500m 직선 거리의 서로 다른 노드 쌍 100개를 고정한다. 가장 짧게/계단 회피/벤치 휴식/휠체어 조건을 25개씩 적용했다. 한국 시각 2026-11-11 10:00을 고정하며 공개 등록 운영시간 검사에 사용한다. 부모 프로세스는 표본을 만들기 위해 자료를 적재했고, 첫 작업 스레드는 새로 자료를 적재했다. 첫 스레드 요청도 표본에 포함한다.

| 항목 | 결과 |
| --- | ---: |
| 순차 HTTP 요청 | 100건, 응답 오류 0 |
| 조건 검사 후 기술 시연 후보 있음 / 없음 | 69 / 31 |
| 가장 짧게 후보 있음 | 25/25 |
| 계단 회피 후보 있음 | 22/25 |
| 벤치 휴식 후보 있음 | 21/25 |
| 휠체어 후보 있음 | 1/25 |
| 후보를 받은 요청의 p50 / p95 / 최대 | 2,415 / 5,223 / 5,705ms |
| 첫 작업 스레드 요청 | 3,731ms |
| 10개 동시 요청 | 처리 4건, 과부하 429 거부 6건 |
| 동시 처리 4건의 기술 시연 후보 있음 / 없음 | 3 / 1 |
| 동시 처리 응답 p95 | 7,145ms |

후보 없음 31건과 429 응답을 빠른 경로 성공으로 집계하지 않았다. 69건의 “후보 있음”은 현장 통과·안전 판정이 아니다. 휠체어 등에서 막힌 조건을 완화하지 않았다. 동시 처리 4건은 후보 없음 응답도 포함하므로 성공 후보만의 지연 지표와 구분한다.

서울 100쌍·동시 10개·p95 3초 목표는 아직 미검증/미달이다. 현재 범위에서조차 후보 p95가 3초를 넘고 큐가 4개로 제한된다. 큐를 크게 늘려 지연과 메모리를 숨기지 않는다. 다음은 반복 도형 검사·선분 연결·후보 계산의 프로파일링과 공통 엔진 의미를 유지하는 성능 개선이며, 실제 호스팅 자원/부하·전역 그래프 검증은 별도다.

```sh
node donghaeng-nav/scripts/benchmark-walk-api.mjs
```

비교 측정은 기존 파일을 보존하도록 두 번째 인자에 새 보고서 이름을 지정한다. 예: `node donghaeng-nav/scripts/benchmark-walk-api.mjs walk-api-followup-performance`. 원래 보고서는 덮어쓰지 않는다.
