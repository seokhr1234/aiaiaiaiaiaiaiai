# 운영 배포 완료와 브랜치 구조 대조

확인: **2026-11-14 KST**. 사용자 요청에 따라 최신 기능을 실제 운영 주소
**https://donghaeng-gill.vercel.app**에 반영했다.

이전에는 feature 배포가 성공해도 운영 주소는 구 main 화면을 제공했다.
이번에는 검증된 feature 커밋 `7c884b209697e1dfded7bb7bb6c5fe4011d09ef2`를
main에 반영했고, 공개 화면과 API가 바뀐 것을 확인했다. 기록만 보고 운영 성공을
판정하지 않았다. [원문 검사 결과](production-deployment-2026-11-14.json).

## 두 브랜치의 구조를 어떻게 처리했는가

이전 main `89d3463`과 feature `7c884b2`는 내부 코드·추가 모듈/자료가 다르다.
다만 다음 공통 진입 경로는 유지돼 있었다.

| 항목 | 이전 main | 배포한 feature |
| --- | --- | --- |
| 루트 launcher | `server.mjs` → `donghaeng-nav/server.mjs` | 같은 경로·같은 루트 launcher 바이트 |
| 실제 화면 소스 | `donghaeng-nav/dist/` | 같은 경로, 서울 화면·추가 모듈 포함 |
| Vercel Output Directory | `donghaeng-nav/dist` | 동일 |
| Vercel 함수 | `api/index.mjs` | 같은 진입 경로, 새 서비스 분기/import 포함 |
| API rewrite | Gemini 상태/문장 해석 2개 | 기존 경로 유지, 선택/자료/서울 도보/대중교통 등 12개 |
| 서비스 디렉터리 | 새 확장 서비스 없음 | `donghaeng-nav/services/`와 그 자산/무결성 기록 포함 |

따라서 화면 파일 몇 개만 덮어쓰지 않고 검증된 커밋의 코드·자료·배포 설정을 함께
반영했다. GitHub 원격 main이 예상한 `89d3463ce5e4441e5a0e0ac069aaadf1024f0ec0`
인지 확인하고, 그 커밋이 feature의 조상임을 확인한 뒤 **force 없이 fast-forward**했다.
기존 main 이력과 연구 자료를 지우지 않았다. 작업 브랜치는 그대로 유지한다.

main 갱신 후 연결된 두 Vercel 프로젝트의 상태가 모두 success였고, 별도 Vercel
설정 변경이나 수동 도메인 이동 없이 Git 운영 배포로 공개 주소가 갱신됐다.

## 배포 후 남은 범위

운영 연결과 새 API의 실제 실행은 확인했다. 서울 전역의 검증된 보도망·교량/지하/
층위 연결·휴식·휠체어 접근성·GPS 경로 안내, 정밀 원본/DEM·현장 조사와 제공업체
실제 인증/검색은 기존 남은 작업으로 유지한다. 이번 배포일을 자료 수집일이나
측량일로 바꾸지 않았다. OSM 원본 수집일은11월11일, 자료 기준은11월9일이다.

11월13일의 배포 미반영/404 기록은 당시 결과로 보존한다. 현재 운영 상태는 이
기록과 실제 공개 응답을 우선한다.
