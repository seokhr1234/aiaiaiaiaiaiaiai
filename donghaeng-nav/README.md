# 동행길 · 서울사대부중 현장 시연 MVP

현재 위치와 목적지, 상태 문장을 입력하면 학교 주변 실제 OpenStreetMap 도로 그래프를 탐색합니다. 기본 경로 탐색은 외부 키 없이 동작하며, 선택적으로 Gemini를 이용해 상태 문장을 해석할 수 있습니다.

## 실행
Node.js 18 이상에서 다음을 실행합니다.

```sh
node server.mjs
```

http://127.0.0.1:4173 에 접속하세요. 서버는 같은 폴더의 `.env`에서 Gemini 키를 읽고, 브라우저에는 키를 보내지 않습니다. `.env`는 `.gitignore`에 포함되어 있으므로 공유하거나 저장소에 올리지 마세요. 키 없이도 앱의 기기 내 규칙 기반 해석과 경로 탐색은 계속 사용할 수 있습니다. 휴대폰 GPS는 배포된 HTTPS 주소에서 사용하세요.

## 시연
1. 학교 주변에서 '현재 위치 사용' → 위치 권한 허용. 실내 오차가 크면 지도에서 변경하거나 출발 핀을 끌어 보정.
2. 목적지는 기본 '종월2교'를 사용하거나 검색 결과/지도에서 선택.
3. '가장 짧은 거리로 가고 싶어요' 입력 후 길 찾기.
4. 같은 출발/목적지로 '중간에 벤치에 앉아 쉬고 싶어요' 입력 후 재탐색.
5. 기본 시연 출발점 기준 최단 약 674m, 벤치 경유 약 958m로 실제 경로가 변경됨. GPS 출발점은 결과가 다를 수 있음.
6. 구간 상세에서 시뮬레이션 또는 GPS 이동 확인 선택.

## 구현
- Leaflet 실제 지도, GPS 위치·정확도 표시, 출발/도착 핀 선택·드래그
- 포함된 학교 주변 공개 장소 검색 (전국 검색 아님)
- Gemini 기반 상태 문장 해석(선택)과 기기 내 규칙 기반 대체, 수정 가능한 조건 칩
- Dijkstra 탐색, 등록 계단 제외, 경사·노면·도로 속성 가중치, 실제 OSM 벤치 경유
- 최단 경로 비교, 구간별 상세, GPS 경로 근접 여부·추정 남은 거리
- 브라우저 로컬 경로 저장/재탐색/삭제 및 제보 저장
- 지도 타일 연결 실패 시에도 포함된 벡터 도로망과 경로 계산 가능

## 한계
- `Gemini로 이동 조건 확인`을 누르면 입력한 상태 문장만 서버를 거쳐 Gemini API로 전송합니다. 위치·목적지·지도 데이터는 보내지 않으며, 서버는 이 문장을 저장하지 않습니다. Gemini 연결에 실패하거나 버튼을 누르지 않으면 기기 내 문장 규칙을 사용합니다. 어느 경우든 해석된 조건을 반드시 확인·수정할 수 있습니다.
- 도로 데이터는 OSM 스냅샷이며 등록되지 않은 계단, 보도 턱·폭, 실제 진입 가능 여부를 보장하지 않습니다. 교내 길 안내는 지원하지 않습니다.
- 경사 대부분 미확인입니다. 수치를 임의 생성하지 않으며 경사 회피 충족을 보장하지 않습니다.
- 지도 핀에서 도로망까지 연결은 미검증 점선이며 거리/시간은 도로 부분만 계산합니다. 벤치의 접근 연결도 별도 표시합니다.
- 벤치는 현장 검증 전이며, 최대 700m 추가 우회 범위에서 후보를 찾습니다. 찾지 못하면 휴식 조건 미충족을 표시합니다. 전체 휴식 간격 보장은 제공하지 않습니다.
- GPS는 경로상 가까운 점으로 투영한 추정 진행 정보입니다. 자동 경로 재탐색/회전 음성 안내는 없습니다.
- GPS 위치·몸 상태는 서버로 전송하지 않습니다. 배경 지도 조회는 OSM 서버를 사용합니다. 저장 버튼을 누른 상태/경로와 제보는 현재 브라우저 localStorage에 저장됩니다.
- 실제 휴대폰의 현장 GPS와 시설 상태는 별도 현장 확인이 필요합니다.

## 검증
```sh
node --check dist/app.js
node --check dist/engine.js
node --check server.mjs
node scripts/test-engine.cjs
```
문장 해석/부정 표현, 계단 제외, 실제 벤치 경유, 동일 출발·도착의 경로 변경, 데이터 범위 밖 실패를 검사합니다. 브라우저에서 경로 탐색·상태 변경·구간 상세·시뮬레이션·저장을 확인했고 390px 화면에서 가로 넘침이 없는 것을 확인했습니다.
