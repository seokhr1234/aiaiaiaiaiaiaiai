# OSM 교차 검증과 근거 품질 조사

조회일: 2026-10-30 (KST). 담당: OSM·교차 검증. 앱 코드는 변경하지 않았다.

## 결론

현재 원본에서 사용할 수 있는 접근성 단서는 있지만, 통행 가능 판정에 필요한 측정 데이터는 매우 적다. 특히 실제 엔진이 채택하는 4,463개 way 가운데 수치 경사는 `incline=0%`인 1개뿐이다. 태그 누락을 평지·턱 없음·출입 가능으로 채우면 안 된다. 이 보고서는 기존 파일을 직접 집계하고 OSM 공식 태그·검증 문서를 인터넷에서 확인한 결과다. 새로운 현장 관찰이나 지역 거리뷰 사진 판독은 수행하지 않았다.

- 실제 확보·분석: `donghaeng-nav/dist/map-data.json`, `dist/engine.js`, `scripts/fetch-map.py`.

- 수집 쿼리: 도로 way는 bbox `(37.580,127.020)–(37.611,127.058)`, POI는 `(37.584,127.025)–(37.607,127.053)`. 학교 기준점은 `(37.5950991,127.038992)`.

- 20,965 node, 4,762 way, relation 0개. 엔진 채택 way 4,463개, 사용 node 19,023개, 최대 연결 성분 node 18,677개.
- 개별 요소의 `timestamp`, `version`, `changeset` 필드는 모두 없다. 원본 ID는 있으나 현재 파일만으로 각 속성의 편집 시점·현장 확인일을 복원할 수 없다.
- 수집 쿼리가 `entrance`, `barrier`, `kerb`, 관계를 독립적으로 모두 요청하지 않는다. 도로에 연결되지 않은 장벽·출입구가 추출에서 빠질 수 있다. 따라서 아래의 0건은 지역에 없다는 뜻도, OSM 전체에 없다는 뜻도 아니다.
- 기계 판독 결과와 예시 OSM ID/URL: [osm-audit.json](osm-audit.json).

거리뷰에서 문이 열려 있거나 보도가 보이더라도 현재 통행 허용·실제 최소폭·정확한 턱 높이·종단/횡단 경사를 확정하지 않는다. 가림·원근·촬영연도·공사·주차 변화가 있다. 이번 조사에서 학교 주변에 실제 열람 가능한 사진이 충분히 있는지까지 확인한 것은 아니다. 따라서 사진 기반 현장 관찰값은 새로 생성하지 않았다.

## 현재 엔진과 데이터의 차이

1. **경사:** 정규식이 단순 숫자와 %만 읽는다. up/down/yes는 unknown 처리된다. % 앞 공백이나 각도 표기는 추가 처리가 필요하고, 현재 절댓값 처리로 오르막/내리막 방향 차이를 잃는다. 스냅샷의 숫자 경사 1개만 수치로 사용된다.
2. **보도:** `sidewalk`만 사용하므로 `sidewalk:both=separate` 등 9개가 누락된다. 반대로 별도 보도 연결·좌우 횡단을 확인하지 않고 차도 쪽 경로에 보도 존재만 적용해서도 안 된다.
3. **턱·폭·횡단:** width/kerb/crossing/smoothness를 현재 경로 비용·통과 조건에 쓰지 않는다. 횡단 데이터가 원본에 존재하는데 UI에서 ‘미수집’이라고 표기하는 부분은 후속 구현에서 원본 태그와 구분해야 한다.
4. **장벽:** 출발·도착 snap에서는 일부 gate/bollard를 고려하지만 `shortest` 경로 중간의 gate/lift_gate/bollard/kerb에 대한 조건은 충분하지 않다. 시작점만 통과 조건을 검사해도 전체 통행 가능이 되지 않는다.
5. **출입:** way의 access=no/private와 foot 예외를 다루지만 permit·시간조건·운영시간은 해석하지 않는다. node access 검사에서는 foot 예외와의 일관성 검토가 필요하다.
6. **층·방향:** 도로를 양방향 간선으로 만들며 conveying/oneway:foot/층간 승강기 연결을 경로 통행 조건으로 충분히 처리하지 않는다. 에스컬레이터를 계단 없는 휠체어 경로로 바꾸면 안 된다.
7. **연결:** 시작·끝을 최대 180m 이내 도로 노드에, 벤치를 최대 35m 이내 노드에 연결한다. 두 위치 사이의 담장·수로·차도 횡단·층 차이는 거리만으로 검증되지 않는다.

이 항목은 코드와 데이터의 대조 결과이며 실제 장애물의 존재를 새로 확인했다는 뜻이 아니다.

## 앱에 적용하기 전 합칠 근거 구조

- 원본 속성값과 해석 결과를 별도 보관한다. unknown/registered/observed/measured/estimated 등 확인 수준, 속성별 observed_at, source_url, source_id, 대상 geometry/방향/층을 둔다.
- 현재 스냅샷은 `registered` 수준이며 실측 근거가 있는 항목만 measured로 올린다. source=survey만으로 자동 승격하지 않는다.
- 정밀도가 부족한 자료를 경로 간선에 강제로 적용하지 않는다. 인근 위치뿐 아니라 같은 보행면·출입구·층·횡단 방향인지 확인한다.
- 충돌하는 출처는 하나로 덮지 말고 병기한다. 최신이라는 이유만으로 측정법이 다른 값을 대체하지 않는다.
- 새 수집에는 필요 지역의 kerb/barrier/entrance/crossing과 관련 relation 및 메타데이터를 포함하되 대량 반복 조회는 피한다. 미등록 시설은 여전히 현장 확인 대상이다.
